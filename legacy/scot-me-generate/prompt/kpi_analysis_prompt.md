# KPI故障树解析脚本生成Prompt

**用途**: 本Prompt用于指导AI根据任意故障树文档生成一个Python脚本，该脚本能够解析kpiTree CSV数据并生成KPI分析结果。

---

## 一、理解输入文件

### 故障树文档（参数化）
- 第一步：用户提供故障树Markdown文件路径（作为脚本输入参数）
- 内容: 包含多层级故障分析树，以`##`标记失败场景，以`###`标记具体故障原因

**关键信息隐藏在文档中**:
- 话统计数器: 形如 `N.XXX` 或 `L.XXX`（如N.QosFlow.Est.Succ）
- 判断方法: 描述如何通过话统计数器判断故障

### kpiTree CSV数据（参数化）
- 第二步：用户提供kpiTree CSV目录路径（作为脚本输入参数）
- 格式: 每行是一个JSON字符串（CSV第一行是表头`KpiTreeJson`）
- 编码: 需根据实际文件编码（常见为GBK或UTF-8）

**关键字段**:
| 字段 | 说明 | 示例 |
|------|------|------|
| id | KPI唯一标识 | "150001" |

---

## 二、识别数据处理难点

### 难点1: 故障树中的计数器污染
故障树Markdown中提取的计数器可能带有HTML污染:
- `N.RadioRes.AllocFail.BBRes<span` ← 末尾多了`<span`
- `N.Paging.Dis.PchCong<` ← 末尾多了`<`
- 实体引用如`&gt;`、`&lt;`也可能存在

**思考**: 如何设计一个清洗函数，既能去除污染又不会误删正常字符?

### 难点2: 嵌套JSON解析
CSV每行是字符串包裹的JSON:
```
xxx
```

**思考**: 如何正确解析这种嵌套格式? json.loads需要什么预处理?

### 难点3: 计数器匹配
需要建立故障树计数器 ↔ kpiTree公式中计数器的对应关系

**思考**: 
- 故障树计数器在kpiTree中存在意味着什么?
- 如何统计一个计数器在所有公式中的出现次数?

## 三、脚本设计指引

### 3.1 计数器提取流程
```
故障树Markdown文本
    ↓ 用什么正则匹配 N. 或 L. 开头的字符串?
原始计数器列表 (可能包含污染)
    ↓ 清洗函数需要做什么?
干净计数器列表
    ↓ 如何验证清洗结果?
清洗后的计数器列表
```

### 3.2 KPI加载流程
```
CSV目录路径
    ↓ 遍历所有.csv文件
逐文件读取 (需自动检测或根据参数指定编码)
    ↓ 逐行解析JSON
KPI列表
    ↓ 按id去重
去重后KPI列表
    ↓ 提取所有formula
公式列表 → 提取计数器集合
```

### 3.3 核心分析逻辑
对于每个故障树计数器，需要判断:
1. **in_kpi_tree**: 该计数器是否出现在任何kpiTree公式中?
2. **usage_count**: 该计数器在整个KPI库中出现了多少次?

同时需要收集使用了故障树计数器的KPI详情:
- 哪些KPI使用了该计数器?
- 该KPI的公式完整内容是什么?

### 3.4 输出结构设计
思考最终输出的JSON应该包含哪些顶层字段?

**建议结构**:
```json
{
  "summary": { /* 统计摘要 */ },
  "counters_needed": [ /* 故障树计数器列表 */ ],
  "counter_coverage": { /* 每个计数器的覆盖情况 */ },
  "matched_kpis": [ /* 匹配的KPI详情 */ ]
}
```

---

## 四、覆盖率计算

覆盖率 = 在kpiTree中存在的计数器 / 故障树总计数器 × 100%

**思考**:
- "存在"的定义是什么?出现在任一公式中即可?
- 如果一个计数器在多个公式中出现，是算1次还是多次?

---

## 五、验证生成脚本

脚本运行后应验证:
1. 计数器列表干净，无`<span`等污染
2. JSON输出结构完整，字段齐全
3. 覆盖率计算正确
4. matched_kpis中的matched_counters数量与实际匹配

---

## 六、关键提示

1. **CSV编码**: kpiTree CSV可能有GBK/UTF-8等编码，建议作为参数传入或自动检测
2. **JSON解析**: 嵌套JSON需要用`json.loads`解析
3. **计数器格式**: 必须以`N.`或`L.`开头，后跟字母数字下划线
4. **去重依据**: 按KPI的id字段去重
5. **引号处理**: 公式中的计数器带引号，提取时需注意
6. **参数化设计**: 故障树路径、CSV目录路径、输出路径应作为命令行参数或函数参数传入
