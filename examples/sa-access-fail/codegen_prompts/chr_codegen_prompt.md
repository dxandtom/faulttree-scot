# chr 解析脚本生成提示词(由元提示词为「SA场景接入失败」生成)

> 三级链中间产物示例:元提示词读了本场景子树 + chr 数据格式后,产出这份"查 chr"的提示词;再由它生成 `chr_analyzer.py`。

请写一个解析 chr 数据的 Python 脚本,满足:

## 〇、最高铁律:只查数据,绝不下判断
- 脚本唯一职责:把数据**忠实地查清楚、统计出来**。
- **绝不**输出 `hit`(是否成立)、`judgment`/结论、"存在 XX 原因"这类判断;**绝不**在脚本里构造判断条件、算占比是否超阈值。占比怎么算、是否超过 30%/20%、是否成立 —— **全部交给 fault-tree-rca**。
- 数据里没有的字段如实标 `found:false`,不编。

## 一、理解输入
- chr 数据为表格(首行表头),含 `Time`、`DCErrType`、`CellId` 等字段。
- 脚本要**自包含**:内联一个读取函数(支持 csv/xlsx + 编码检测),**不要 import 任何本仓自定义模块**。
- 本场景故障子树引用到的 chr 字段/取值(只需"取出计数",不要判断):`DCErrType` 的取值 `RrcReject`、`TransLink`。

## 二、数据驱动地遍历 + 统计(别写死字段)
- **自动发现表头里实际有的列**并逐列统计,不要把列清单写死:
  - 类别列 → 取值分布(top-N 计数)+ 每个值附几个样例标识(优先 ID 类列,否则行号);
  - 数值列 → count / min / max / mean。

## 三、定向提取故障树引用到的东西(只取值,不判断)
- 把 `DCErrType` 的 `RrcReject`、`TransLink` 各自的**出现次数**取出来,连同**总记录数**、所在列(`where`)、几个样例一起摆出。
- **不要**算占比、不要和 30%/20% 比、不要给 `hit`。比对留给 RCA。
- 若数据里没有 `DCErrType` 列 → 标 `found:false`。

## 四、输出 JSON(只有事实,没有判断)
- 顶层:`indicator`、`summary`(记录数 + 字段名)、`field_stats`(每个字段的分布/数值摘要)、`referenced`(子树引用的取值计数)。
- `referenced` 每项形如:`{"found":true,"where":"DCErrType","count":<计数>,"total":<总数>,"samples":[...]}`。
- **通篇不得出现** `conditions` / `hit` / `judgment` / "成立/不成立/根因" 等字样。

## 五、工程要求
- Python 3.11;参数:数据文件、`-o/--output`;**自包含**(内联读取,不 import 本仓模块);中文注释;路径加引号;可直接运行。
