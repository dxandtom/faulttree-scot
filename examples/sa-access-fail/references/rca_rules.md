# 根因分析规则(fault-tree-rca)

## 输入
- **fault_tree_md**:故障子树正文。`#/##/###` 表层级;每个标题下跟着该节点的判断条件正文。由人工编写,**可能格式不一致、逻辑跳跃或有笔误**。
- **indicator_results**:各指标解析脚本输出的 JSON,键为指标名。每个里有 `conditions` 数组,每项**已由脚本确定性算好**:
  - `expr`:故障树判断条件(逐字);
  - `values`:用到的实际数值(结构化);
  - `actual`:实际数值的文字描述(如 `N.RRC.SetupFail.NoRes = 60`);
  - `judgment`:代入后的比较过程 + 结论(如 `60 > 0 → 成立`);
  - `hit`:是否成立(true/false)。

## 目标
判定故障子树中**所有成立**的故障路径,输出:根因 + 从根到该节点的完整路径 + **把"证据是什么、怎么判断的"讲清楚**的判断依据。

## 步骤
1. **解析子树**:识别每个节点的名称、层级、其下的判断条件正文。
2. **匹配条件**:对每个节点,在 `indicator_results[*].conditions` 里找到对应 `expr`,**直接采用**它的 `actual` / `judgment` / `hit`(**不要重算数字**)。若脚本没覆盖到某条件,再依据指标明细判断;遇到子树不规整/笔误,用判断力合理推断,但不得臆造数据。
3. **回溯路径**:对每个 `hit` 成立的(最深)节点,向上回溯到根,得到完整路径(含根因节点)。
4. **多路径**:**所有**成立的路径都输出,各成一个数组元素。

## 输出契约
```json
[
  {"Root_cause":"根因节点名称",
   "Fault_tree_path":["父节点1","父节点2","根因节点"],
   "evidence_path":[
     {"node":"父节点1","condition":"<逐字判断条件>","actual":"<实际数值>","judgment":"<代入比较 → 成立/不成立>"},
     {"node":"父节点2","condition":"...","actual":"...","judgment":"..."},
     {"node":"根因节点","condition":"...","actual":"...","judgment":"..."}
   ]}
]
```

## evidence_path 标准(核心契约 —— 必须把"证据 + 怎么判断"写清楚)
`evidence_path` 与 `Fault_tree_path` **一一对应**,每个元素是一个对象,**四个字段都要填清楚**:
- **`node`**:节点名。
- **`condition`**:该节点在故障树正文里的判断条件,**逐字摘抄**(保证能追溯回原始规则,不改写)。
- **`actual`**:这条条件用到的**实际数值**,写明白。例:`N.RRC.SetupAtt.Sum = 1200, N.RRC.SetupSucc.Sum = 1100`。
- **`judgment`**:**怎么判断的 + 结论**——把实际值代进条件、算出来、给结论。例:`1200 - 1100 = 100 > 0 → 成立`。

> `condition` / `actual` / `judgment` 直接取自该节点对应的解析脚本 `conditions` 项(`expr` / `actual` / `judgment`),**不要自己重算数字**——脚本已经算好。
>
> **反例(老版本的错误)**:evidence 只写一句 `N.RRC.SetupFail.NoRes > 0` 是不够的——看的人不知道实际值多少、到底成不成立。**必须**带上 `actual` 和 `judgment`。

- 若某节点是纯描述性的路径中间节点、没有判断条件:`condition` 与 `actual` 置空串 `""`,`judgment` 写 `路径中间节点,无独立判断条件`。

## 分工
- 数值的加减/比较/计数/占比,以及 `actual` / `judgment` 的文字 —— **解析脚本(script 步骤)已经算好**,RCA **直接采用**,不要重算。
- RCA 负责模型擅长的部分:组合判断、路径回溯、逐节点取证、处理子树不规整,并把依据组织成上面的结构。这样既稳(数字靠代码)又清楚(依据完整可读)。
