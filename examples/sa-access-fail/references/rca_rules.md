# 根因分析规则(fault-tree-rca)

## 输入
- **fault_tree_md**:故障子树正文。`#/##/###` 表层级;每个标题下跟着该节点的判断条件正文。由人工编写,**可能格式不一致、逻辑跳跃或有笔误**。
- **indicator_results**:各指标解析脚本输出的 JSON,键为指标名。每个里有:
  - `summary`:摘要;
  - 指标抽取明细;
  - `conditions`:数组,每项 `{expr, values, hit}` —— 脚本已**确定性算好**的每条判断条件命中结果。

## 目标
综合各指标数据,判定故障子树中**所有成立**的故障路径,输出:根因节点 + 从根到该节点的完整路径 + 与路径一一对应的逐字判断依据。

## 步骤
1. **解析子树**:识别每个节点的名称、层级、其下的判断条件正文。
2. **匹配条件**:对每个节点的判断条件:
   - 优先采用 `indicator_results[*].conditions` 里已算好的 `hit`;
   - 若脚本没覆盖到某条件,再依据指标明细数据判断;
   - 故障树是人工写的,遇到格式不一致/跳跃/笔误时**用你的判断力**做合理推断(这正是这一步用模型而非纯规则的原因),但**不得臆造数据**。
3. **回溯路径**:对每个成立的(最深)节点,向上回溯到根,得到完整路径(含根因节点本身)。
4. **多路径**:**所有**成立的路径都要输出,各成一个数组元素。

## 输出契约
```json
[
  {"Root_cause":"根因节点名称",
   "Fault_tree_path":["父节点1","父节点2","根因节点"],
   "evidence_path":["对应父节点1的依据","对应父节点2的依据","对应根因节点的依据"]}
]
```

## evidence_path 标准(必须严格遵守 —— 这是本 skill 的核心契约)
1. 与 `Fault_tree_path` **一一对应**:第 N 个 evidence 对应第 N 个节点。
2. 每个 evidence **逐字摘自该节点在故障树正文里的判断条件**,**不得**改写、补充、推断或组合。
3. **不得**把 `indicator_results` 里的实际数值拼进 evidence。
4. 若某节点正文没有明确判断依据(纯描述性节点),该位置置**空串** `""`。

**正例**:节点"RNL异常"正文写着 `N.QosFlow.FailEst.RNL > 0`,则其 evidence 就是 `N.QosFlow.FailEst.RNL > 0`。

**反例**:`N.QosFlow.FailEst.RNL > 0 (实际 37)` —— 括号里来自数据、不是故障树正文,**错误**。

## 与确定性计算的分工
- 数值的加减、比较、计数、占比**已在解析脚本里算好**(`conditions`),**直接采用,不要重算**。
- 你的职责仅是:组合判断 + 路径回溯 + 逐字取证 + 处理子树不规整。这样既稳(数字靠代码)又灵(判断靠模型)。
