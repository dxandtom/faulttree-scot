# 代码说明总目录

本目录是 `skills/` 下各技能代码的接手说明，面向接手本项目的开发同事。每个技能一份文档，先讲技能在整体流程中的位置与文件之间的配合，再逐个文件说明功能与实现。读之前建议先看 `docs/design.md`，它用一页说明七个技能怎样组成生成、执行、评估、优化的闭环。

## 建议阅读顺序

| 顺序 | 文档 | 技能 | 在流程里的位置 |
|---|---|---|---|
| 1 | [cs-scot-generate.md](cs-scot-generate.md) | 生成 | 把故障树 Excel 与各数据源编译成场景技能：树索引、执行计划、逐条件分析脚本、调优表 |
| 2 | [cs-scot-execute.md](cs-scot-execute.md) | 执行 | 场景技能的执行指引与执行器：按执行计划运行分析脚本，压缩故障子树，交给根因分析 |
| 3 | [fault-tree-rca.md](fault-tree-rca.md) | 执行 | 根因分析：程序汇总节点状态、选候选、定结论等级，模型只判断证据矛盾的候选，程序拼装结果与报告 |
| 4 | [zip2csv.md](zip2csv.md) | 执行（辅助） | 把原始采集文本转成日志、配置、命令回显三类表 |
| 5 | [datacom-fault-tree-tester.md](datacom-fault-tree-tester.md) | 优化（业务侧） | 业务专家把一个节点的判断方法整理成文档与判断脚本，打成节点交付包 |
| 6 | [cs-scot-migrate.md](cs-scot-migrate.md) | 优化 | 把节点交付包适配进场景技能：替换判据与绑定，按对应表增删节点，刷新工具链公共文件 |
| 7 | [cs-scot-reflect.md](cs-scot-reflect.md) | 评估 | 用用例库评估诊断结果：对账、六类错误分类、评级与评分，一键回归 |
| 8 | [cs-scot-generate-optimize.md](cs-scot-generate-optimize.md) | 优化（入口） | 生成与优化的统一入口：识别输入形态，按评估反馈生成处理清单，发行打包 |

## 文档里的统一用词

代码注释与运行时提示里仍有一些项目内部说法，说明文档一律改用下面的叫法，读代码时可对照：

| 文档用词 | 含义 | 代码或注释里可能见到的写法 |
|---|---|---|
| 内核算子 | `condition_kernels.py` 里按类别执行判据计算的函数，共 A 阈值比较、C 字段匹配、G 日志匹配、D 多条件组合、P 成对比较、J 人工确认、S 节点判断脚本七类 | 内核、kernel |
| 算子绑定 | 分析脚本 `CONDITIONS` 列表里的一个条目，把一条判据映射到某数据源的某一列和某类算子的参数 | 绑定、binding |
| 事实 | 分析脚本对一条判据的计算结果：计算状态、是否命中、实际值、证据片段 | fact |
| 节点状态 | 一个节点多个数据源的事实汇总后的状态：成立、不成立、证据矛盾、数据不足 | 三态、tri |
| 候选清单 | 根因分析第一步由程序生成的文件：成立的最深节点列为候选，附证据路径与程序给出的结论等级 | 骨架、rca_draft |
| 结论等级 | 候选的四种结论：确证根因、疑似根因、待确认、排除 | 档、定档、verdict |
| 模型判断结果 | 模型对证据矛盾的候选给出的判定与理由 | 裁决单、decisions |
| 与之矛盾的上级节点 | 路径上实测不成立或证据矛盾的上级，使候选只能作疑似根因 | 卡点、blocked_at |
| 程序对结果的检查 | 拼装根因分析结果时的一组拒绝条件 | 结构闸、结构检查 |
| 绑定指向的节点在故障树里已不存在 | 通常是删了节点没清绑定 | 孤儿绑定、orphan |
| 任务说明 | 生成阶段为每个子代理准备的自包含文件，装着一批判据、数据概览与绑定规则 | 简报、briefing |
| 节点交付包 | 业务专家交付的 zip：判断方法文档、判断脚本、共享解析库、测试数据 | 交付包、package |
| 对应表 | 平台批量交付时每行一个节点、写明对应 zip 的表；平台全量表就是它 | 对应表、map |
| 迁移记录 | 场景技能里记录每个节点迁自哪个包、内容指纹、时间的文件 | 台账、ledger |
| 工具链公共文件 | 与场景无关、由工具链维护的文件：内核算子库、执行器、数据入口检查、转换脚本、根因分析副本 | 标准件、engine |
| 格式检查 | 对判断脚本与交付包的机械检查，共十条要求 | 契约检查、check_contract |
| 处理项、处理清单 | 优化入口对评估报告里每条问题给出的处理方式，以及它们的集合 | 票、工单、tickets |
| 自动档、人工档 | 处理项的两档：自动档在优化循环内直接执行，人工档汇总交人 | auto、fallback |
| 同一 skills 目录下的其他技能 | 与某技能并列安装的其他技能 | 同门 |

## 各技能目录的共同约定

- 每个技能目录下 `SKILL.md` 是给模型执行的操作手册，`references/` 是手册引用的细则，`scripts/` 是脚本。
- 场景技能是生成环节的产物，它的 `assets/` 目录装着执行计划、分析脚本、树索引、调优表与根因分析规则副本；执行、迁移、评估、优化四个环节都读写它。
- `cs-scot-migrate/engine/` 是其他技能文件的副本，由 `sync_engine.py` 维护，供本技能单独安装时使用；修改源文件后要同步副本。
