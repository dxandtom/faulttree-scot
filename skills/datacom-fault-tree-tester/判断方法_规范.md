# 判断方法文档规范

> 本规范定义了「判断方法.md」文件的结构、内容要求和编写指南。

---

## 一、文件命名

```
判断方法_<故障场景名>.md
```

示例：`判断方法_接口UP但无流量.md` 或 `判断方法_V-STP根桥桥MAC配置异常.md`

---

## 二、必填字段

### 2.1 节点名称
- **位置**：文档开头
- **内容**：故障树节点的唯一标识名称
- **格式**：
  ```markdown
  ## 节点名称
  V-STP根桥桥MAC配置异常
  ```
- **要求**：简洁、明确，能区分不同故障节点

### 2.2 故障描述
- **位置**：节点名称之后
- **内容**：用一句话简洁描述要检测的故障现象及其影响
- **格式**：
  ```markdown
  ## 故障描述
  在设备重启时，如果 V-STP 根桥未配置桥 MAC 或配置的桥 MAC 不是 V-STP 协商出来的 Active 桥 MAC，
  由于 V-STP 需要同步桥 MAC，会导致网络震荡超过 10s。
  ```

### 2.3 判断条件
- **位置**：故障描述之后
- **内容**：逐条列出故障判断所需的条件
- **格式选择**：
  - **并行条件**：用「条件 A」「条件 B」「条件 C」编号（条件间无依赖）
  - **顺序步骤**：用「步骤 1」「步骤 2」「步骤 3」编号（条件间有前置依赖）

#### 2.3.1 并行条件格式（无依赖关系）
- **每条条件需包含**：
  1. **条件名称**：如「物理接口过滤」「接口状态检查」
  2. **具体规则**：描述匹配的规则或排除的条件
  3. **匹配方式**：正则表达式、关键字匹配、数值比较等

```markdown
### 条件 A：物理接口过滤
- 排除以下接口类型：
  - `vlanif`（VLAN接口）
  - `eth-trunk`（链路聚合接口）
  - 子接口（接口名包含 `.`）

### 条件 B：接口状态检查
- `current state` 字段值必须为 `UP`
```

#### 2.3.2 顺序步骤格式（有依赖关系）
当判断条件存在前置检查时，使用「步骤」描述：

```markdown
### 步骤 1：检查 V-STP 使能状态
- 命令：`display current-configuration`
- 检查内容：是否存在 `stp v-stp enable`
- 条件：存在
- 结果：
  - 是 → 执行步骤 2
  - 否 → 不匹配

### 步骤 2：检查是否为根桥
- 命令：`display stp`
- 检查内容：CIST Root/ERPC 字段
- 条件：包含 "This bridge is the root"
- 结果：
  - 是 → 执行步骤 3
  - 否 → 不匹配

### 步骤 3：对比桥 MAC 配置
- 3.1 提取配置的桥 MAC
  - 正则：`stp bridge-address\s+([0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4})`
- 3.2 提取 Active MAC
  - 命令：`display stp v-stp`
  - 正则：`Bridge\s+Mac\s*:\s*\S+\s*/\s*Active=([0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4})`
- 3.3 对比判断
  - 不一致 → 故障
```

**顺序步骤的要求**：
- 每个步骤需说明：满足条件后执行下一步，不满足则不匹配
- 最终步骤说明匹配/不匹配的判断标准

### 2.4 命中条件
- **位置**：判断条件之后
- **内容**：用布尔表达式描述各条件的逻辑关系
- **格式**：
  ```markdown
  ### 命中条件
  (A 且 B) 且 C
  ```
  或
  ```markdown
  ### 命中条件
  A 且 (B 或 C)
  ```

### 2.5 输出
- **位置**：命中条件之后
- **内容**：说明匹配的输出结果
- **格式**：
  ```markdown
  ## 输出
  当检测到 <具体故障条件> 时，输出故障。
  ```

### 2.6 数据来源
- **位置**：输出之后
- **内容**：说明判断所需数据的获取方式
- **必须指定**：
  - **命令**：如 `display interface`、`display current-configuration`
  - **目录**：`CONFIG/`、`CMD/`、`LOG/`（三选一或组合）

**格式示例**：
```markdown
## 数据来源
| 数据类型 | 命令 | 目录 |
|----------|------|------|
| 设备配置 | `display current-configuration` | CONFIG/ |
| 诊断命令 | `display stp`, `display stp v-stp` | CMD/ |
| 日志信息 | `display logbuffer` | LOG/ |
```

## 三、选填字段

### 3.1 适用产品
- **位置**：数据来源之后
- **内容**：说明判断方法适用的产品范围
- **格式**：
  ```markdown
  ## 适用产品
  华为 CE 系列交换机（支持 V-STP 特性）
  ```

### 3.2 示例数据
- **位置**：适用产品之后（或数据来源之后）
- **内容**：提供真实的配置/命令输出示例
- **格式要求**：
  - 直接展示命令输出片段
  - 标注关键字段的位置
  - 简述分析结论

**格式示例**：
```markdown
## 示例数据

### CONFIG 中的相关配置：
```
stp mode rstp
stp v-stp enable
```

### display stp 输出：
```
CIST Root/ERPC      :32768.8ce5-ef19-5601 / 0 (This bridge is the root)
```
分析：`This bridge is the root` 表明是根桥，满足步骤 2 条件

### display stp v-stp 输出：
```
Bridge Mac          :Config=8ce5-ef19-5601 / Active=8ce5-ef19-5601
```
分析：Active MAC 为 `8ce5-ef19-5601`
```

### 3.3 注意事项
- **位置**：示例数据之后
- **内容**：补充说明判断逻辑的特殊处理、边界情况等

**格式示例**：
```markdown
## 注意事项
- 仅检测根桥设备，非根桥设备不参与判断
- 桥 MAC 配置大小写不敏感，统一转为小写比较
```

## 五、编写指南

### 5.1 条件描述要求
| 要求 | 说明 | 错误示例 | 正确示例 |
|------|------|----------|----------|
| 具体化 | 给出具体的字段名、值、格式 | 接口UP | `current state` = `UP` |
| 可执行 | 能转化为正则或代码逻辑 | 端口状态正常 | `current state` 包含 `UP` 且不包含 `DOWN` |
| 无歧义 | 避免模糊表述 | 流量较低 | `Last * seconds input rate` = 0 |

### 5.2 何时使用「条件」vs「步骤」？
| 场景 | 格式 |
|------|------|
| 条件间无依赖，可并行判断 | 使用「条件 A/B/C」 |
| 条件间有前置依赖，必须按顺序 | 使用「步骤 1/2/3」 |

### 5.3 正则表达式规范
如需使用正则表达式，请按以下格式标注：
```markdown
### 步骤 3：提取 MAC 地址
- 正则：`stp bridge-address\s+([0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4})`
- 说明：提取形如 `xxxx-xxxx-xxxx` 的 MAC 地址
```

### 5.4 数据来源规范
| 数据类型 | 命令 | 目录 |
|----------|------|------|
| 设备配置 | `display current-configuration` | CONFIG/ |
| 接口统计 | `display interface` | CMD/ |
| 诊断命令 | `display stp`, `display vlan` | CMD/ |
| 日志信息 | `display logbuffer`、`display trapbuffer` | LOG/ |

## 附录：脚本生成通用要求

> 生成 `fault_check_*.py` 脚本时，必须遵循以下要求

### 1. 必须复用 `search_config.py` 通用解析模块

**位置**：`scripts/search_config.py`

**要求**：脚本必须使用 `search_config.py` 中提供的通用解析函数，**禁止**自行实现配置解析逻辑

```python
# 正确示例
from search_config import parse_config_file, find_config_item, get_group_items

config_groups = parse_config_file(config_file_path)
matched_groups = find_config_item(config_groups, 'interface Vbdif', use_regex=True)
```

**原因**：`search_config.py` 已经实现了：
- 文件编码自动检测（GBK/GB2312/UTF-8）
- 以 `#` 分隔的配置块解析
- 大小写不敏感的搜索功能

### 2. 正则表达式必须大小写不敏感

**原因**：华为设备配置中，关键字大小写不固定（如 `interface Nve1` vs `interface nve1`）

**要求**：
- 使用 `find_config_item(..., use_regex=True)` 进行大小写不敏感搜索
- 或在正则中使用 `[Nn][Vv][Ee]` 字符类

```python
# 正确
find_config_item(config_groups, 'interface Nve1', use_regex=True)

# 错误：只匹配小写
find_config_item(config_groups, 'interface nve1', use_regex=False)
```

### 3. 配置块分割必须使用 `#` 分隔符

**原因**：设备配置以 `#` 作为配置块边界，自行使用前瞻匹配 `(?=interface\s|\Z)` 可能导致同名接口匹配重叠

**要求**：使用 `search_config.py` 的 `parse_config_file()` 函数，它内部已正确处理 `#` 分隔

### 4. 三态诚实：数据缺失必须明说，禁止冒充结论

**原因**：脚本结论会被下游根因分析当事实用。数据没采到却输出 matched:false，下游会把
"没数据"当"排除该故障"，把根因带偏；解析失败后降级全文搜关键字继续判，会把坏数据判成
"故障成立"（更危险的假阳）。

**要求**：
- 某网元判定所需数据缺失（命令没采集、目录/文件缺失、解析失败）→ 该网元输出
  `{"error": "缺什么"}`（**不带** matched 字段）
- **禁止**：缺数据时输出 matched:false 冒充"正常"；把缺数据的网元从结果里静默剔除；
  解析失败后换一种方式硬判

```python
# 正确
if not config_files:
    results[ne_name] = {"error": "CONFIG 目录下没有配置文件"}
    continue
config_groups = parse_config_file(config_file)
if not config_groups:
    results[ne_name] = {"error": "配置文件解析不出配置块（文件损坏或格式异常）"}
    continue

# 错误：解析失败降级继续判 —— 空文件会被判成"四项配置全缺失 = 故障成立"
if not config_groups:
    content = read_raw(config_file)          # ← 禁止这种后备路径
    ...
```

### 5. 统一入口与输出形状

**要求**：
- 唯一对外入口：`diagnose(data_dir)`，返回 `{"网元名": {"matched": bool, "evidence": [...],
  "details": {...}}}`（或该网元的 `{"error": "..."}`）；内部函数怎么组织不限
- `print` 只允许出现在 `if __name__ == '__main__'` 分支（import 调用时零副作用）
- **读 `sys.argv` 同样只允许在 `__main__` 分支**：库调用时 sys.argv 是宿主进程的命令行，在 `diagnose()` 内部拿 `sys.argv[N]` 当默认参数会吃进宿主的参数（实测:把宿主的 -o 输出路径当正则用,直接炸）。函数参数的默认值写成字面量
- 判断方法.md 的「数据来源」表必须列全脚本实际用到的每条命令（下游按它核对采集覆盖）
