# cs-scot-migrate — tester 交付包一条龙迁移

## 干什么

业务同事用 datacom-fault-tree-tester 技能产出的交付包,内含**人确认过**的判断方法文档和
**样本数据验证过**的诊断脚本。本技能把它装进我们的场景产物:

- **a. 判据替换**:交付包 判断方法.md **全文逐字**替换到故障树对应节点的判据上(故障描述/判断条件/命中条件/输出/数据来源表/注意事项一个不丢,进「判据:原文」列)——树上的判据从此就是整份规范文档,数据来源表留作核对采集覆盖的依据;
- **b. 绑定换血**:该节点旧绑定全部清掉,换一条 S 绑定(`func=fault_check` 通用转接头),
  执行时直接跑交付的脚本——**脚本一行不改,判断逻辑照单全收,对错归脚本**。

全程走产物自带的调优表往返(export → 改一行 → import),复用其全部校验;迁移台账记在
`产物/tree/migrations.json`。

## 输入

| 参数 | 说明 |
|------|------|
| 交付包 | `<节点名>.zip` 或解压后的目录(内含 判断方法.md + fault_check_*.py);**多节点合集包**(zip 里套多个节点 zip/子目录)也直接给,配合 `--auto` 批量循环 |
| 场景产物目录 | 生成链路的产物目录;打包成技能形态的话给它的 `assets/` 目录 |

> **别做手册没要求的预检(实测教训:预检烧了十几分钟,命令本身几十秒跑完)**:
> 节点对不对得上、包里有什么、树里有没有同名节点——全是第 1 步命令自己的产出
> (精确匹配→候选清单→语义对号三级兜底),不是你的前置作业。拿到包和产物目录,
> **直接跑第 1 步**,按退出码办事。
> **禁止用 `python -c`/自写临时脚本解析 tree_index/调优表/产物 JSON**:Windows 上
> 中文路径经 shell 传递必乱码、字段结构靠猜必错(实测连环三炸)。要看内容,用本技能
> 脚本自己的打印输出;还不够就把文件路径报给用户看。

## 流程(对号三级:代码 → 模型 → 人)

### 第 1 步:先试自动对号(代码精确匹配)

```bash
python skills/cs-scot-migrate/scripts/migrate_fault_check.py \
    --package <交付包> --product <产物目录> --auto
```

- 交付包节点名与树上某节点**一字不差且唯一** → 脚本直接落地迁移,到此结束,不用打扰用户;
- 没有精确命中 → 打印候选列表(相似度排序,退出码 3),进入第 2 级。

**多节点合集包(批量)**:命令一模一样——`--auto` 遇到合集包自动逐子包循环,能精确对号的
**一轮手术原子落地**(任一行编译不过整批不生效),对不上号/探不到入口的决不赌,结尾统一列清单,
每个附好补对号命令。之后没对上的逐个走第 2/3 级:

```bash
python skills/cs-scot-migrate/scripts/migrate_fault_check.py \
    --package <合集包> --product <产物目录> --only "<包节点名>" --node <节点号>
```

(`--only` 从合集包里选定一个子包,其余单节点参数 `--entry`/`--per-ne`/`--entry-kwargs` 都可配。)

**对应表批量(推荐给平台侧批量交付)**:同事提供一张对应表(**xlsx 或 csv**)——层级列 + `zip` 列,
每行 = 一个节点:按「名字路径」定位树节点(**同名节点靠全路径自动消歧**,不用人指定),
按 zip 列把合集里的包对号入座。

- **表头怎么写都认**(格式没跟交付方钉死,宽进):层级列裸 `L1`/`L2`…、`L1(Chinese)`、`L1(中文)`、
  全角括号、大小写、带空格都行;**没有 node_id**(有 node_id 的会被当成我们的调优表拒收);
  zip 列叫 `zip`(或唯一一个列名含 zip 的);zip 值带/不带 `.zip` 都行;
  **平台1 导出表直接给也认**(`L1_Name_CN`/`L1_Name_EN` 成对 + `Product_Obs` + `Product_Name`,
  层级动态):节点定位取 `_Name_CN` 列,`_Name_EN` 与 `Product_Obs`(obs 下载地址,工装层的事)
  整列忽略,`Product_Name` 当 zip 列——zip 包本身先由联调驱动按 `Product_Obs` 下载到位
  (见 `integration/platform1/`);
  **判据列可选**(表头含 判据/判断方法/判断条件/judgment/judgement 的列;平台1 增强表的
  `judgement_condition_cn`/`_en` 成对时取 cn 弃 en)——在场即启用下面的清除行与判据同步语义,
  老表没有此列行为一切照旧;
- **行语义三种**(全量表口径,机械分类):
  | 判据格 | zip 格 | 含义 | 动作 |
  |---|---|---|---|
  | 有值 | 有值 | 迁移行 | 对号迁移(主路径);**判据以表为准**(界面是用户最后编辑的状态,与包内判断方法不一致的注记+返厂点名) |
  | 有值(或表无判据列) | 空 | 结构行:节点在,没配包 | 表有判据列且与树上不同 → **只同步判据(绑定一格不动)**,汇总单列 `~`;表无判据列零动作 |
  | **空** | **空** | **清除行**:用户在界面上删了该节点的判据与包 | **清该节点的判据+绑定**(节点保留) |
- **清除行纪律**:走调优表手术同一合规通道(原文列+全部绑定列清空→import 编译),逐个点名播报;
  **幂等**(判据已空的跳过,全量表重复给不怕);迁移过的节点台账记 `cleared_at`(评估反思的
  清绑定合规通道按"台账有记录+绑定空"认,不误开工单);定位失败不赌不清、进失败清单;
  `--no-clear` 只点名不执行;**清除≠删节点**——删整节点仍走调优表删行,人确认;
- **表可以直接打在交付包里**:脚本自动发现(包里恰一张"层级列+zip 列"的表就按它走,多张硬停要求指定);
  也可 `--map <表路径>` 显式指;
- 对应不上的行(zip 找不到/路径定位失败/全路径重名)逐行点名进失败清单,退出码 3,
  其余行照常**一轮手术原子落地**;包里没被表引用的子包会列出来(未迁移);
- 表里路径与包内「节点名称」不一致时以**对应表为准**(汇总里注记);
- **全量交付幂等**(每次全量给包也没关系):内容指纹与台账一致的包**自动跳过**——没变的不动,
  此后的人工调优不会被全量重迁冲掉;`--force` 强制全部重迁;
- **增节点自动做**(加法可回滚、有台账):表里出现**全树都没有的新节点**且其父路径能唯一定位
  → 自动在父节点下新建(判据=判断方法全文、绑定=S 脚本、node_id 由导入自动分配,不需要表里有
  node_id),汇总里单列 `+ 新增`;父节点也是本次新增的,跑第二遍即落(第一遍落父、第二遍落子);
- **全量对账**:台账里迁移过、这次表里**已无该节点**的(上游可能删了)/节点还在但**没配 zip** 的
  (优化包撤了?)——结尾分别点名,默认**不自动删树**(减法必须人确认);确认真要删,
  调优表删掉该行再 import 即生效,或直接用下面的 `--map-mode all`;
- **`--map-mode` 三档**(对应平台优化按钮的 optimizeType,缺省 `auto`=上述旧默认):
  - `multi`(部分表):**不动树结构**——迁移行/清除行/判据同步照做,新增节点行硬拒点名
    (增删节点请走全量表);
  - `all`(全量表):**树结构以表为准**——新增节点照旧;**纯判据行也能新增**结构节点
    (仅判据无绑定);**双空行定位不到的也补建**(平台的无判据结构层导出就是双空,平台树有、
    本地没有 → 建裸节点,它名下的新叶子第二遍运行挂上);整张表(迁移/结构/清除行路径并集)
    里**踪影全无的节点自动删**(与路径定位同一套子序列语义,候选天然含整棵子树)。
    删除走调优表删行同一合规通道,调优表 `.bak` 可回退、台账记 `deleted_at`,汇总单列 `✂`。
    三道保险:树根名在表里踪影全无 → 判定表和树对不上,一个不删;节点深度超出表层级列数
    (表表达不了)→ 不删只点名;**删除候选超过全树一半 → 判定"部分表被误标成 ALL",
    一个不删**(确属大改版加 `--force` 放行)。

**处理方式按输入自动定**(一条命令走天下,不用挑模式):

```bash
python skills/cs-scot-migrate/scripts/migrate_fault_check.py \
    --package <交付包(单包/合集目录/zip)> --product <产物或技能目录> --auto [--map <表>]
```

| 输入长什么样 | 自动走哪条 |
|---|---|
| 包里有对应表(或 --map 给了) | 对应表批量(路径定位+zip 对号) |
| 无表 + 多节点合集 | 逐子包精确同名对号批量(没对上的列候选) |
| 无表 + 单节点包 | 单节点流程(精确命中直接落地) |
| 带 --node/--only 等手工参数 | 人工指定优先,自动发现不介入 |

### 第 2 级:模型语义对齐

看候选列表和交付包的判断方法,判断哪个节点与交付包是**同一个故障**(名字变体很常见,如
「V-STP根桥桥MAC配置异常」vs「V-STP根桥未配置桥MAC」)。**确信**是同一节点 → 直接执行落地,
并在汇报里写明"按语义把「<包节点名>」对到了 <节点号>「<树节点名>」":

```bash
python skills/cs-scot-migrate/scripts/migrate_fault_check.py \
    --package <交付包> --product <产物目录> --node <节点号>
```

### 第 3 级:拿不准就问人

候选分数接近、或都不像同一个故障 → 把候选列表给用户,让用户指定节点号,再执行落地。
**禁止在拿不准时赌分数最高的。**

脚本自动完成:**引擎体检+补全**(旧产物/打包技能里的 condition_kernels、custom_lib、
import 校验、runner 不认 S 类 → 从引擎源刷新并 .bak 备份——同事拿旧 execute 打的包也能收。
按**能力标记**只补缺、不追平:文件能力齐全就一律不碰,绝不把更新的产物降级。引擎源自包含:
优先本机同门 cs-scot-generate/execute,没有就用本技能自带的 `engine/` 目录,单装本技能也能迁)
→ **契约体检+补库**(两档处置,见下节)→ 拷脚本进 `scripts/custom/` → 调优表手术(判据/绑定)
→ import 编译回产物 → 调优表回导同步 → cross 骨架过旧则就地升级 → 写迁移台账。

入口函数自动探测(diagnose/main/check_ne…);探测不准时报错或告警,按提示加
`--entry <函数名>`、`--per-ne`、`--entry-kwargs '<JSON>'` 重跑。**探测不到就问用户/看脚本,
不许瞎猜函数名。**

## 硬规矩

- 对号按三级走:精确同名唯一 → 代码自动;语义明确 → 模型对齐并在汇报里写明对应关系;
  **拿不准 → 必须问人**,禁止赌分数。
- 调优表比产物新时(可能有未导入的人工修改)脚本会**先自动 import 收编再继续**——表填坏了
  import 会响亮失败、迁移就地打住,把报错原样给用户,别替它圆。
- **不改交付脚本的判断逻辑**:发现脚本可疑(如解析失败还继续判)→ 告诉用户反馈给交付方,
  不"顺手修"。契约体检点名的**管道**问题(入口/后缀/输出形态这类)按下节修**副本**是允许的;
  判断逻辑仍然一行不动。
- 脚本报错时把报错原样给用户,产物不会半截落地(手术在 import 校验全过后才生效)。

## 收编体检与管道修复(两档处置)

落绑定前每个脚本过一道**契约体检**(与 tester 同一份 `check_contract.py`,`engine/` 有内置
副本,单装本技能也能用),按"下游转接头兜不兜得住"分两档:

- **WARN(兜得住)→ 放行,脚本一行不动**:入口旧名、单网元风格、布尔 matched、按网元字典、
  argv/print 纪律这类,转接头运行时都兜(仲裁/护现场/形态归一)——记台账 `contract_warns`
  并进返厂清单;
- **FAIL(兜不住,执行必受影响)→ 不落绑定,进修复循环**:只认 .txt 漏 log.log、缺数据冒充
  false、import 三方件这类。脚本副本连同修复基准会先落到 `scripts/custom/`(`<脚本>` +
  `<脚本>.orig`),照体检输出的修法**只修管道副本**(判断逻辑一行不动,拿不准算不算逻辑 →
  问用户,不赌),改完**重跑同一条迁移命令**续迁——包没变时修复副本不会被包里原件覆盖,
  体检绿了绑定才落地。

配套机制:

- **补库**:脚本 import 的 `search_*.py` 包里没带 → 从同门 tester/`engine/` 兜底拷入
  (违规记返厂清单;正本必须自包含,规范附录8);
- **回归保险**:包里带 `测试数据/` 时体检自动试跑记基线;修复后基线 matched 与修前不一致 →
  拦下——管道修复不许改变判断结论;
- **返厂清单**:汇总结尾把每个包"已兜的 WARN / 已修的管道 / 缺的库"点名——副本兜住的只是
  本次执行,正本的窟窿必须回到交付方手里(或用 tester 的「批量翻新已交付包」把正本刷新),
  否则每次全量交付都复活一遍;
- 修复留痕:台账字段 `contract_warns`/`repairs`;`scripts/custom/` 下 `.orig`(修复基准)+
  `<脚本名去后缀>.contract.json`(体检记录)。想丢弃修复按包里原件重来:删对应 `.orig` 再
  `--force` 重迁。

## 无包翻新(--refresh-only)

手头没有交付包、只想把旧产物/旧打包技能刷到当前代(custom_lib/内核/导入导出/runner/
check_data/zip2csv/**fault-tree-rca 规则副本**〔自动定档+机械报告这一代,整目录刷新,
旧副本备份 fault-tree-rca.bak〕/SKILL 正文〔含机械渲染报告指引〕)时:

```bash
python skills/cs-scot-migrate/scripts/migrate_fault_check.py --product <产物或技能目录> --refresh-only
```

全部按能力标记**只补缺不降级**,动过的文件都有 .bak 备份,技能名/描述等身份信息不动。

## 迁移后

- 执行诊断时可加 `--data raw=<zip2csv 输出的 extracted 目录>`,让脚本直读原始 txt(最忠实);
  不加也能跑,转接头会从 config/log/cmd 三表自动重建。
- 结果三态:任一网元命中→成立;全网元报错/无网元→**数据不足**(不冒充"正常");其余→不成立。
- 证据保真:脚本给的**命中原文(matched_items)、出处文件(source_files)、判定理由(details.reason)**
  逐字进事实(定长截断防上下文爆炸),随 rca_input 一路带进根因报告的 evidence_path。
- **打包说明**:迁移就地生效——产物就是打包技能的 `assets/` 时,技能已更新完毕,**无需重新打包**;
  只有在独立产物目录上迁移、之后要发布成技能时才跑 package_scenario.py。
- 同一节点重复迁移(交付包更新)= 直接重跑第 2 步,台账覆盖更新。

## 维护(工具链开发者看,业务使用无关)

`engine/` 是内核/函数库/调优表往返/骨架/runner 的内置副本,让本技能不依赖同门技能也能补全
旧产物。cs-scot-generate / cs-scot-execute 侧改了这些文件后,跑一次
`python skills/cs-scot-migrate/scripts/sync_engine.py` 对齐。
