# cs-scot-generate-optimize：生成与优化的统一入口

## 任务

按下面的判定表认出输入的形态，找到对应线的手册，照那本手册执行。本入口自己不实现任何一步，也不改各线的任何步骤。

判定的是模型，不是代码：本入口没有分发程序，是模型读表照做；各线内部才有真代码（migrate 分辨单包、合集、对应表；generate 分辨新老格式母表）。所以判定依据一律用客观可查的特征（文件里有没有某列、有没有某个文件），认不出就问用户，不猜。

## 术语

| 术语 | 含义 |
|---|---|
| 母表 | 业务从现网导出的故障树 xlsx：有层级列，没有 zip 列，也没有 node_id 列 |
| 对应表 | 平台批量交付时的表：层级列加 zip 列，写明每个节点对应哪个交付包 |
| 调优表 | 场景产物自带的人机接口 xlsx：带 node_id 列，用 export_tree_excel.py 导出、import_tree_excel.py 导回 |
| 层级列、zip 列、node_id 列 | 认表的三个特征列。层级列如 L1、L2 或 `L1(Chinese)`；zip 列指向交付包；node_id 列是产物里的节点编号 |
| 交付包 | 业务同事用 datacom-fault-tree-tester 产出的单节点包：`判断方法*.md`（文件名不含"规范"）、测试数据、可选的 `fault_check_*.py` |
| 合集包 | 多个交付包放在一起，各子目录各有一份判断方法文档 |
| 产物目录 | generate 生成的场景产物，含 `tree/*.tree_index.json`、`scripts/`、`plan.json`；技能形态下在 `assets/` 目录 |
| 既有产物 | 已存在的产物目录；除生成线外，其余三条线都作用在它上面 |
| 票 | 反馈处理线由 route_feedback.py 对每条问题开出的处置单：写明该走哪条通道、做什么 |
| 自动档、人工档 | 票的两档：自动档在优化循环内直接照票执行；人工档是自动化做不了的情况，汇总交人 |
| 熔断 | 同一节点同一类问题连续三轮没改好，自动转人工 |
| 发行包 | package_skill.py 打出的自包含包，两线与公共素材平铺在包根，交付平台用 |

## 执行规矩

- 本入口只做路由，不改各线手册的步骤，不合并各线代码，不代替各线校验。
- 认出线之后，不做手册没要求的预检。包里有什么、树上对不对得上，是各线第一步命令的产出，不是前置作业（实测手工预检要十几分钟，命令本身几十秒）。不用 `python -c` 或临时脚本解析 tree_index 和产物 JSON，Windows 中文路径会乱码、字段靠猜必错；要看内容用各线脚本的打印输出，不够就把文件路径报给用户。
- 判定表认不出的输入，把看到的文件形态描述给用户请其指认，不挑一条"最像的"硬走。
- 删除类动作（删节点、删绑定）无论来自谁的建议，都必须用户确认后才执行。
- 各线内部的规则（不泄露答案、vendor 引擎不改、不引入第三方库、任务说明不占上下文等）写在各线手册里，进线即生效。

## 认输入形态

判定分三层，不要混：

```
一条线   = 若干"标志"中任一个命中        （优化线有 3 个标志，命中一个就是它）
一个标志 = 若干"特征"同时满足            （少一条就不是这个标志）
必需入参 ≠ 标志                          （不参与认线，是定线之后的清点清单）
```

| 线 | 标志（任一命中） | 特征（同时满足） |
|---|---|---|
| 生成线 | 母表 xlsx | 有层级列，且没有 zip 列，且没有 node_id 列 |
| 优化线 | ① 交付包 ② 合集包 ③ 对应表 | ① 有 `判断方法*.md`（文件名不含"规范"）；② 多个子目录各有一份判断方法文档；③ 有层级列且有 zip 列 |
| 增删节点线 | 用户明说增删 | 用户明说增或删节点，且没有交付包 |
| 反馈处理线 | 评估报告或反馈 JSON | 有 `meta.verdict` 和 `reconciliation`（评估报告）；或条目含 `error_class`，取值在六类错误名里（反馈或失败签名） |

母表那三条特征必须同时判：只有"有层级列、无 zip 列、无 node_id 列"同时成立，才能与对应表（有 zip 列）、调优表（有 node_id 列）区分开。少判一条就会把对应表当母表去建树。

匹配规则：

1. 认线看标志，命中一个标志就定线，不要求入参齐全。看到 `判断方法*.md` 就是优化线，哪怕还不知道要装到哪个产物。
2. 开跑看入参，必需项必须全齐；缺一样就停下问用户要，不用默认值凑、不自己编路径、不在文件系统里搜。
3. 多条线的标志同时命中是混合输入，不是冲突，按"混合输入"一节的顺序逐条跑。
4. 一个标志都不命中，就把看到的文件形态描述给用户请其指认。

## 四条线的入参与手册

| 线 | 做什么 | 必需入参 | 可选入参 | 手册 |
|---|---|---|---|---|
| 生成线 | 建树、组装、绑定、校验，直接生成场景技能 | 母表 xlsx；场景名（用于截取子树并命名，`--start-node`）；每种指标一份数据（csv 或 xlsx；原始日志 txt 或 zip 先转成三张表） | 产物落点 `--out-base`，默认母表旁的 `scot技能/<短名>/` | generate |
| 优化线 | 替换判据、更换绑定；单包、批量、翻新 | 交付包、合集或目录；场景产物目录（`--product`，技能形态给它的 `assets/`） | 包里有 `fault_check_*.py` 则判据和脚本一起迁，没有则只迁判据、由人改调优表，这不是错误；对应表 `--map`（批量模式用，包里自带一张也会自动发现）；`--auto` 批量循环（合集包用） | migrate |
| 增删节点线 | 通过调优表增删节点 | 产物目录；增：父路径、节点名、判据原文（可带绑定）；删：节点名或 node_id，加用户明确确认 | | 本文"增删节点线" |
| 反馈处理线 | route_feedback 开票，自动档照票执行，记账，全库回归 | 评估报告或反馈 JSON；产物目录 | 交付包目录（重迁票要用，有就带上） | 本文"反馈处理线" |

生成线是唯一不要既有产物的线，它就是产生产物的。其余三条线都作用在已有的树上，没有产物目录无处生效。用户只给了交付包却没说装到哪，问用户要产物目录，不在文件系统里找，更不新建一个空产物。

同是 xlsx 的三种表，拿到先看列，不看文件名：

| 特征 | 是什么 | 去处 |
|---|---|---|
| 层级列，无 zip 列，无 node_id 列（多页签新格式与单页签 `L1(Chinese)` 老格式都算） | 母表 | 生成线入口 |
| 层级列加 zip 列 | 对应表 | 优化线批量模式 |
| 带 node_id 列 | 调优表 | 不是入口输入；增删节点线和人工小改用 |

生成与优化的分界是有没有既有产物：目标目录里有 `tree/*.tree_index.json`（技能形态看 `assets/` 下）就是既有产物，交付包、增删、反馈都作用在它上面；没有既有产物只能先走生成线。

## 手册怎么找

每条线的手册按下面次序找，找到第一个就用（与 generate 找 zip2csv 的次序相同）：

1. 发行包形态：`<本目录>/generate/SKILL.md`、`<本目录>/migrate/SKILL.md`（发行包把两线放在子目录）。
2. 仓库形态：`<本目录>/../cs-scot-generate/SKILL.md`、`<本目录>/../cs-scot-migrate/SKILL.md`（开发时的兄弟目录）。

发行包形态下唯一的路径改写规则：子手册命令里的 `skills/cs-scot-generate/`、`skills/cs-scot-migrate/` 前缀，换成 `<本目录>/generate/`、`<本目录>/migrate/`（用绝对路径）；`skills/zip2csv/` 等素材前缀换成 `<本目录>/zip2csv/`（素材平铺在包根）。除此之外照手册逐字执行，不增不减。

发行包自带公共素材 `cs-scot-execute/`、`fault-tree-rca/`、`zip2csv/`，与两线目录平铺在包根。包根扮演仓库 `skills/` 目录的角色：generate 按"同一 skills 目录下的其他技能"这一级找素材能命中，migrate 也一样。所以发行包形态的生成线同样直接生成完整可执行的场景技能。素材目录只是打包原料，判定表不因此多出一条线；执行诊断的入口在生成出来的场景技能里，不在本入口。

## 混合输入

固定顺序是先生成后优化（前者的产出是后者的输入），不并行、不跳步：

| 同时给了 | 执行顺序 |
|---|---|
| 母表、指标数据、交付包 | 生成线全程（产物生成）→ 优化线迁入交付包 |
| 交付包、明确的增删指令 | 优化线（带对应表时包内新节点自动走增加分支；没有表的新节点走增删节点线，或让交付方补对应表）→ 增删节点线处理剩余的增删 |

## 增删节点线

一切通过产物自带的调优表往返完成（导出、改表、导回），校验、台账、孤儿绑定处理全部复用：

- 增：`python "<产物>/scripts/export_tree_excel.py" --out "<产物>"` 导出调优表；新加一行，node_id 留空由脚本分配，写清父路径、判据原文、绑定；`python "<产物>/scripts/import_tree_excel.py" --out "<产物>"` 导回。有交付包的新节点不走这条，交优化线自动建（判据和 S 类绑定一次带齐）。
- 删：先向用户复述"将删除节点 X 及其绑定，不可自动恢复"，得到明确确认后，在调优表删该行并导回。评估反思或任何自动建议的删除，同样只到"点名"为止，用户同意才执行。
- 改判据、改绑定不算增删：量大走优化线（交付包），单行小改直接改调优表再导回。

## 反馈处理线

承接 cs-scot-reflect 的评估输出。三种产物都认，按机械特征：

- `evaluation_report.json`：有 `meta.verdict`（PASS、PASS_WITH_GAPS、PARTIAL_PASS、FAIL、EVAL_ERROR）和 `reconciliation` 对账块；要处置的条目在 `failure_signatures` 与 `verdict_detail`。
- `feedback_to_generate.json`、`failure_signatures.json`：条目含 `error_class`（或 `error_category`），取值在 ENV_FAILURE、INPUT_GAP、BINDING_GAP、KNOWLEDGE_GAP、CRITERIA_GAP、VERDICT_GAP 六类里。

第一个动作是跑分拣脚本开票，不对着反馈自由发挥：

```bash
python "<本目录>/scripts/route_feedback.py" --feedback <评估输出json> --product <产物目录>
```

脚本机械判定每条问题的真因（台账反查交付包、定位孤儿绑定、按节点名对时、拼装证据、识别熔断），开出处置票，分两档：

- 自动档：脚本崩溃重迁、孤儿绑定清理、绑定缺失补挂、用例库过期重生成、判定偏差修复（修到与判据文档一致）。循环内直接照票执行，不等确认；执行完全库重跑重评进入下一轮；同节点同类三轮不过由熔断自动转人工。
- 人工档：环境故障、数据缺失、绑定清除冲突、故障树缺节点、结论归档争议、熔断票。自动化本来就做不了的情况，汇总交人。

每轮执行完记账：

```bash
python "<本目录>/scripts/route_feedback.py" --record <票单> --done all --product <产物目录>
```

写入产物的 `tree/feedback_log.json`（改了什么的历史，与评估目录的各轮报告对账，事后可审计）。

四条规则：

1. 以判据文档为准。脚本和绑定放开修，修到与判断方法文档一致为止；判定标准一个字不动。要改标准等于缺知识，退回 tester 改正本。这是防止"改判据来通过用例"的关键。
2. 按轮次全量回归。处置完必须全用例库重跑执行和评估，不许只验单个用例；同节点同类三轮不过自动熔断转人工（评估侧自动计数）。
3. 评估隔离。看过反馈的会话等于知道该用例的答案，回归验证必须派独立会话。
4. 留痕审计。每轮自动记账；人工档与熔断票必须人处理；自动档只许执行票面写的动作，不越票发挥。

每种票走哪条通道、做什么动作，以及 verdict 各取值的处理，见 `references/feedback_routing.md`。执行票时对照它。

## 发行打包

```bash
python "<本目录>/scripts/package_skill.py"
```

把本入口、两线、公共素材合成 `dist/cs-scot-generate-optimize/` 并打同名 zip：generate、migrate 与素材（cs-scot-execute、fault-tree-rca、zip2csv）平铺在包根；关键文件逐一核验，缺一个就报错并清理残留；`MANIFEST.txt` 记全部文件与来源提交（工作区有未提交改动标 `+dirty`）；zip 可复现（同一提交两次打包 sha256 一致）。打包是纯复制，不改写任何源文件；输出目录与任何源目录重叠会拒绝执行。本脚本只在仓库开发态可用，发行包内不含它。

## 完整例子

| 用户开场 | 认哪条线 | 第一个动作 |
|---|---|---|
| "用这棵树 `LDP故障树.xlsx` 和 `数据/` 生成 LDP 场景技能" | 生成线（标志是母表） | 三样齐了（树、场景名"LDP"、数据），按 generate 手册开跑步骤 1 |
| "把 `交付包.zip` 迁进去" | 优化线（标志是交付包） | 产物目录没给，问："装到哪个场景产物？给我技能的 `assets/` 目录路径" |
| "帮我把这批包 `合集.zip` 按 `对应表.xlsx` 全量导入到 `scot技能/ldp/assets/`" | 优化线批量 | 齐了，按 migrate 手册的对应表批量模式跑 |
| "给接口层加个'光模块异常'节点" | 增删节点线（增） | 缺产物目录、父路径、判据原文，一次问齐再动 |
| "把 n17 删了" | 增删节点线（删） | 先复述确认："将删除节点 n17 及其绑定，不可自动恢复，确认？"得到明确确认才动手 |
| "这是评估反思的报告，按它优化" | 反馈处理线 | 跑 `route_feedback.py` 开票；自动档照票执行，人工档汇总交人；记账；全库回归 |
