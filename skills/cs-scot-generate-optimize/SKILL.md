# cs-scot-generate-optimize —— 生成/优化前门(只路由,不干活)

**本文件已加载,不要再次加载或调用本技能。你的任务:按下面的判定表认出输入形态 →
找到对应线的手册 → 照那本手册干活。前门自己不实现任何一步,也不改各线的任何步骤。**

## 一步定线:输入形态判定表(全机械特征,查表不猜)

**判定的是你(模型)不是代码**——前门没有分发程序,是你读这张表照做;各线内部才有真代码
(migrate 分辨单包/合集/对应表、generate 分辨新老格式母表)。所以判定依据一律用**客观可查的
特征**(文件里有没有某列、有没有某文件),**认不出就问人,绝不猜**。

**判定结构(三层,别混):**

```
一条线   = 若干「招牌」的 OR    ← 优化线有 3 个招牌,任一个命中就是它
一个招牌 = 若干「特征」的 AND   ← 特征必须全满足,少一条就不是这个招牌
入参【必需】≠ 招牌              ← 不参与认线,是定线之后的清点清单
```

各招牌的特征(括号内 AND 关系,必须同时成立):

| 线 | 招牌(彼此 OR) | 特征(AND) |
|---|---|---|
| 生成线 | 母表 xlsx | 有层级列 ∧ **无** zip 列 ∧ **无** node_id 列 |
| 优化线 | ①交付包 / ②合集包 / ③对应表 | ①有 `判断方法*.md`(文件名不含"规范")/ ②多个子目录各有一份判断方法.md / ③有层级列 ∧ 有 zip 列 |
| 收编线 | 平台规则 JSON | 有 childrenRule ∧ 有 nameZh ∧ 有 script |
| 结构手术线 | 用户明说增删 | 用户明说增/删节点 ∧ 没有交付包 |
| 回流线 | 失败签名 JSON | 条目有 `mechanical` 栏 ∧ verdict 在八枚举内 |

> **招牌内部为什么必须 AND**:母表那三条是**互斥性设计**——只有"有层级列 + 无 zip 列 +
> 无 node_id 列"同时成立,才能与对应表(有 zip 列)、调优表(有 node_id 列)分开。
> 少判一条就会把对应表当母表拿去建树。

**匹配规则:**

1. **认线看招牌——命中一个招牌就定线**,不要求入参齐。看到 `判断方法*.md` 就是优化线,哪怕还不知道
   要装到哪个产物;
2. **开跑看入参——必需项必须全齐**,缺一样**停下问用户要**,别拿默认值硬凑、别自己编路径、
   别在文件系统里瞎找;
3. **多条线招牌同时命中** = 混合输入,不是冲突 → 按 §混合输入的依赖序逐条跑,不要二选一;
4. **招牌一个都不命中** → 响亮问人(把你看到的文件形态描述给用户,请他指认),
   **不许挑一条"最像的"硬走**。

| 招牌输入(认线用,机械特征) | 走哪条线 | 完整入参(跑起来实际要这些) | 手册 |
|---|---|---|---|
| **故障树母表 xlsx**(层级列;无 zip 列、无 node_id 列。新格式多页签与老格式单页签〔`L1(Chinese)` 表头〕皆算,两格式分辨见 generate 手册) | **生成线**:建树→归集→绑定→校验,直出场景技能 | ① 母表 xlsx【必需】② **场景名**(截子树+命名,`--start-node`)【必需】③ 每种指标一份数据(csv/xlsx;裸采集 txt/zip 先转三表)【必需】④ 产物落点 `--out-base`【可选,默认母表旁 `scot技能/<短名>/`】。**唯一不要既有产物的线**——它就是产生产物的 | generate |
| **交付包**(zip/目录,内含 `判断方法*.md`——**这一样就是招牌**,排除文件名带"规范"的)/ 多节点**合集包** / **对应表**(层级列 + zip 列) | **优化线**:判据替换+绑定换血,批量/单包/翻新 | ① 交付包/合集/目录【必需】② **场景产物目录**(`--product`:产物目录,技能形态给它的 `assets/`)【必需,装到哪去】③ `fault_check_*.py`【**包里有则判据+脚本一起迁;没有则只迁判据**,由人改调优表,不是错误】④ 对应表 `--map`【批量模式用;包里自带一张也自动发现】⑤ `--auto` 批量循环【合集包用】 | migrate |
| **平台规则 JSON**(childrenRule 列表,字段 nameZh + script) | **收编线**:脚本当规格书消化成绑定纪要,注入生成线绑定 | ① 规则 JSON(一份或多份)【必需】② **脚本根目录**(节点脚本+公共组件)【必需】③ **产物目录 `<OUT>`,且已走完生成线步骤 1-2**(里面得有 `tree/*.tree_index.json`)【必需前置,没有就先去生成线】 | adopt |
| 用户明说**增/删节点**,且没有交付包 | **结构手术线** | ① **产物目录**(技能形态给 `assets/`)【必需】② 增:父路径 + 节点名 + 判据原文(+绑定)【必需】/ 删:节点名或 node_id + **用户明确确认**【必需】 | 本文件 §结构手术线 |
| **评估反思失败签名/处置清单 JSON**(条目含 `mechanical` 栏 + verdict 枚举) | **回流线(预留)** | ① 失败签名 JSON【必需】② **产物目录**【必需】——目前只认不分发,见 §回流线 | 本文件 §回流线 |

> **一句话记牢:除生成线外,四条线都必须有"既有产物目录"这一样**——它们都是在已有的树上动土,
> 没有它无处落地。用户只丢来一个交付包/规则 JSON 却没说装到哪,**问他要产物目录**,
> 别在文件系统里瞎找、更别新建一个空产物。

**同是 xlsx 的三分辨**(拿到表先看列,别看文件名):

| 特征 | 是什么 | 去处 |
|---|---|---|
| 层级列,**无 zip 列无 node_id 列**(多页签新格式/单页签 `L1(Chinese)` 老格式皆算) | 母表(业务现网导出) | 生成线入口 |
| 层级列 + **zip 列** | 对应表(平台批量交付) | 优化线批量模式 |
| 带 **node_id 列** | 调优表(产物自带的人机接口) | 不是入口输入;结构手术线/人工小改用 |

**生成 vs 优化的分界=有没有既有产物**:目标目录里有 `tree/*.tree_index.json`(技能形态则看
`assets/` 下)即既有产物——交付包/规则 JSON/增删/回流全都作用在它上;没有既有产物,只能先走生成线。

## 手册查找次序(仓库态/发行包态通用)

每条线的手册按此次序找,找到第一个就用(与 generate 内嵌 zip2csv 的查找次序同款):

1. **包内形态**:`<本目录>/generate|migrate|adopt/SKILL.md`(发行包把三线内嵌成子目录);
2. **仓库形态**:`<本目录>/../cs-scot-generate|cs-scot-migrate|cs-scot-adopt/SKILL.md`(开发态兄弟目录)。

**包内形态的路径换算(唯一一条改写规则)**:子手册命令里的 `skills/cs-scot-generate/`、
`skills/cs-scot-migrate/`、`skills/cs-scot-adopt/` 前缀,一律换算成 `<本目录>/generate/`、
`<本目录>/migrate/`、`<本目录>/adopt/`(用绝对路径);`skills/zip2csv/` 换算成
`<本目录>/generate/zip2csv/`。除此之外照手册逐字执行,不增不减。

**包内形态能力边界(发行包不含执行器,别硬闯)**:发行包只带生成/优化三线,
**不含 cs-scot-execute 与 fault-tree-rca**(执行属另一技能节点)。因此包内形态:

- 生成线步骤 1 会自动"退回产物形态"——这是预期行为不是故障;交付止点=产物目录,
  **别跑步骤 5(package_scenario,会因找不到 execute 硬停)**;
- 子手册里凡引用 `<cs-scot-execute 目录>` / fault-tree-rca 的段落(直出技能形态、执行诊断),
  包内形态一律停下向用户明说:需仓库开发态,或本机另装 cs-scot-execute 与 fault-tree-rca;
- migrate 翻新老打包技能的 runner/check_data/zip2csv 补挂**不受影响**
  (engine/ 内置副本与包根 zip2csv 都随包带)。

## 混合输入:按依赖序执行,不并行不跳步

固定顺序 **收编 → 生成 → 优化**(前者的产出是后者的输入):

| 同时给了 | 执行序 |
|---|---|
| 母表 + 指标数据 + 交付包 | 生成线全程(产物落地)→ 优化线迁入交付包 |
| 母表 + 平台规则 JSON + 脚本 | 生成线步骤 1-2 → 收编线(纪要注入)→ 回生成线 2.5 绑定起 |
| 三样全齐 | 生成 1-2 → 收编 → 生成 2.5-4 → 优化线迁移 |
| 交付包 + 显式增删指令 | 优化线(**带对应表时**包内新节点自动走增分支;无表的新节点走结构手术线,或让交付方补对应表)→ 结构手术线处理剩余显式增删 |

## 结构手术线(增/删节点,不经交付包)

一切走**产物自带的调优表往返**(export → 改表 → import,校验/台账/孤儿绑定处理全复用):

- **增**:`python "<产物>/scripts/export_tree_excel.py" --out "<产物>"` 导出调优表 →
  新加一行(node_id **留空**自动分配;写清父路径、判据原文、绑定)→
  `python "<产物>/scripts/import_tree_excel.py" --out "<产物>"` 导回。
  有交付包的新节点**别走这条**,交优化线自动建(判据+S 绑定一次带齐)。
- **删**:**必须人确认后才动手**——先向用户复述"将删除节点 X 及其绑定,不可自动恢复",
  得到明确确认 → 调优表删该行 → import。评估反思或任何自动建议的删除,同样只到"点名"
  为止,人点头才执行。
- 改判据/改绑定不叫手术:量大走优化线(交付包),单行小改直接调优表改行 → import。

## 回流线(预留口子,等评估反思 skill 落地后接入)

**认**:失败签名/处置清单 JSON,机械特征=条目含 `mechanical.class / verdict / route` 字段,且
verdict ∈ {run_invalid, needs_data, needs_repair, needs_binding, needs_knowledge,
needs_criteria_review, needs_adjudication, needs_reconciliation}
(契约=《评估反思飞轮设计与搭建指南》v2 的双栏失败签名)。

**做**:目前**只认不分发**——向用户明说"回流自动分发尚未接入",并按下表把每条 finding 指到
人工通道;**绝不猜格式、不擅自改资产**:

| verdict | 人工通道(即本门各线) |
|---|---|
| needs_data | 补数据清单交使用方(不动本门任何资产) |
| needs_repair | 优化线:migrate 修复循环 / 返厂清单(交付脚本正本刷新在 tester 侧「批量翻新」;产物侧引擎债另有 `--refresh-only`) |
| needs_binding | 生成线 2.5 补绑(有平台脚本则先走收编线注纪要) |
| needs_knowledge | tester 产判断方法 → 优化线增节点收编 |
| needs_criteria_review | 人拍板假设单后:调优表改行 → import |
| needs_adjudication / needs_reconciliation | 只点名给人,不自动处置(删减必人确认) |
| run_invalid | 重跑,不改任何资产 |

接入时只需两件(等评估反思契约定稿):①把"认"的特征收紧成 schema 校验;
②把上表右列换成命令级自动分发(默认 auto=false,逐条人过目)。

## 发行打包(交付平台=一个自包含包)

```bash
python "<本目录>/scripts/package_skill.py"
```

把前门+三线+zip2csv 合成 `dist/cs-scot-generate-optimize/` 并打同名 zip:
generate/migrate/adopt 成为子目录、zip2csv **双落位**(内嵌 generate/ 供生成线查找次序①,
再置包根供 migrate 补挂查找)、关键文件逐一核验**缺一即响亮失败并清残局**、
`MANIFEST.txt` 记全部文件与来源提交(工作区有未提交改动标 `+dirty`)、zip 可复现
(同一提交两次打包 sha256 一致)。打包是纯复制,不改写任何源文件;输出目录与任何
源目录重叠会**拒绝执行**。本脚本仅仓库开发态可用,发行包内不含它;包的能力边界见上节。

## 红线

- 前门**只路由**:不改各线手册的任何步骤,不合并各线代码,不代替各线校验;
- 判定表认不出的输入**响亮问人**,不猜、不硬塞最像的线;
- 删除类动作(删节点/删绑定)无论来自谁的建议,**必须人确认**;
- 各线内部的红线(泄题防线、vendor 引擎不改、零三方件、简报不走上下文等)在各自手册里,进线即生效。
