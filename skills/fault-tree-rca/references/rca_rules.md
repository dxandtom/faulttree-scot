# 根因分析规则(fault-tree-rca)

## 输入
- **fault_tree_md**:故障子树正文(`#/##/###` 层级,标题下是判断条件)。
- **indicator_results**:各指标 parser 产出的**事实**(只有 `summary` / `field_stats` / `referenced`,**没有任何判断**)。
  - `field_stats`:各字段的分布/数值摘要(含样例);
  - `referenced`:故障树引用到的计数器/字段的**取值/计数**(`found`、`value`、`count`、`where`、`samples`、`definition`)。
  - **注意:parser 不下判断。"是否成立"全部由你来算。**

## 你的职责:判断都在这一步
1. 对故障树**每条判断条件**:从 indicator_results 的 `referenced` / `field_stats` 里取出**相关的值/计数/分布**;
2. 套用条件里的**阈值 / 比较 / 算术**(阈值取自故障树,不是你发明的),算出该条件**成立 / 不成立**;
3. 取不到所需的值(`found:false`、或事实里没有)→ 该条件 **数据不足 / 未判定**;**绝不臆造数值**;
4. 一条路径从叶子回溯到根,**路径上每个带判断条件的节点都"成立"** → 才是根因;有节点不成立 → 路径不成立;有节点未判定 → 路径未判定;
5. **没有任何完全证实的路径** → 输出 `[]` + `undetermined`(列出卡在哪些条件、缺什么数据、parser 给的相关 `definition`/`context`);**绝不硬凑、绝不编值编根因**。

## 铁律(真实)
- 只用 parser 给的**真实事实**;evidence 里的 `actual` **逐字引用** parser 的值/计数(如 `N.x = 60`、`RrcReject = 4/10 = 40%`),**不自行编数、不重算不存在的量**。
- `judgment` 是你**现在算**的"把实际值代入条件 → 比较 → 成立/不成立",依据必须是上面取到的真实值。
- 不把 `field_stats` 的分布数硬当某条件"成立";不发明计数器/阈值。
- 聚合数据里可能并存多种失败模式 → **多根因合理,但每个都要完整证实**;路径**去重/合并**,按**支持度**(命中记录数,取自 parser 的 `count`/`samples`)从高到低排。

## 输出契约
```json
[
  {"Root_cause":"根因节点名称",
   "Fault_tree_path":["父节点1","父节点2","根因节点"],
   "support":"主要支持:<命中记录数/样例,取自 parser 事实>",
   "evidence_path":[
     {"node":"父节点1","condition":"<逐字取自故障树>","actual":"<逐字引用 parser 的实际值/计数>","judgment":"<你现在算的:代入比较 → 成立/不成立>"},
     {"node":"根因节点","condition":"...","actual":"...","judgment":"..."}
   ]}
]
```
- 没有完全证实的路径:输出 `[]`,并另给 `undetermined`(关键但未判定的条件 + 缺什么 + parser 给的相关定义/阈值)。
- 无判断条件的中间节点:`condition`/`actual` 置空串,`judgment` 注明"路径中间节点,无独立判断条件"。

## 一句话分工
parser 把数据**查清楚摆出来**(事实);你把这些事实**对照故障树去判断**(成立与否、路径、根因)。两边都不许编。
