# 根因分析规则(fault-tree-rca)

## 输入
- **fault_tree_md**:故障子树正文(`#/##/###` 层级,标题下是判断条件)。
- **indicator_results**:dict,键是指标名,值是该指标**通用引擎**产出的事实/规则(**无任何判断**):
  - 公共:`kind`(`tabular`/`catalog`)、`summary`、`field_stats`(各字段分布/数值摘要)。
  - **tabular(如 CHR)**:`field_stats` 就是各列的真实分布/数值。
  - **catalog(如 kpiTree)**:另有 `rules`(各 KPI 的 `formula`/阈值/定义)、`counter_index`(计数器 → 用到它的 KPI/公式/阈值)。
  - **注意:引擎不下判断、也不替你做"故障树匹配"。投影 + 判断全是你的活。**

## 你的职责:投影 + 判断都在这一步
1. 对故障树**每条判断条件**,先看它依据什么:
   - **CHR 类**(条件点名某列/取值,如 `DCErrType = RNL_Unspecified`、`MSG3 RSRP < -120`、`占比 > 30%`)→ 到对应 `tabular` 指标的 `field_stats` 取该列真实分布/数值,套条件里的阈值/比较/算术 → 算成立/不成立。
   - **话统计数器类**(条件含 `N./L.xxx`,如 `N.UECntx.FailEst.AMF > 0`)→ 这类要**实测值**,而 kpiTree 只有定义。到 `catalog` 的 `counter_index`/`rules` 取该计数器的 `formula`/阈值/含义**作背景**,但**没有实测值 → 该条件如实判"数据不足/未判定"**,绝不拿分布数或 CHR 旁证硬当它成立。
2. 取不到所需值 → **数据不足**;绝不臆造数值。
3. 一条路径从叶子回溯到根,**路径上每个带判断条件的节点都"成立"**才是根因;有节点不成立→路径不成立;有节点数据不足→路径**未判定**。
4. **没有任何完全证实的路径** → 输出 `[]` + `undetermined`(列出卡在哪些条件、缺什么数据、相关 `rule`/`definition`);**绝不硬凑、绝不编根因**。

## 铁律(真实)
- evidence 的 `actual` **逐字引用**引擎给的真实值/计数(如 `RrcReject = 4/10`);**不自行编数、不重算不存在的量**。
- **精确匹配**:故障树要的取值/计数器要**精确**命中(要 `0x810D176C` 就不能拿相近的 `0x810D176B` 顶);命不中 → 数据不足。
- 话统计数器"**无实测值**"是常态:如实判数据不足,**别用 CHR 分布替代话统阈值**。
- 聚合数据可能并存多种失败模式 → 多根因合理,但**每个都要完整证实**;路径**去重 + 按支持度排序**。

## 输出契约
```json
[
  {"Root_cause":"根因节点名称",
   "Fault_tree_path":["父节点1","根因节点"],
   "support":"主要支持:<命中记录数/样例,取自引擎事实>",
   "evidence_path":[
     {"node":"父节点1","condition":"<逐字取自故障树>","actual":"<逐字引用引擎的实际值/计数>","judgment":"<你现在算:代入比较 → 成立/不成立/数据不足>"}
   ]}
]
```
- 没有完全证实的路径:输出 `[]`,并另给 `undetermined`(关键未判定条件 + 缺什么数据 + 相关 `rule`/阈值/定义)。
- 无判断条件的中间节点:`condition`/`actual` 置空串,`judgment` 注明"路径中间节点,无独立判断条件"。

## 一句话分工
引擎把数据**查清楚 / 把规则摆出来**(事实);你拿故障树去**投影 + 判断**(成立与否、路径、根因);**测不到就如实说数据不足**。两边都不许编。
