# fault-tree-rca —— 综合根因分析

**本文件已加载,不要再次加载或调用本技能;"加载"≠"完成",真正产出根因 JSON 才算完成。** 现在立刻三步走(路径以 runner 打印的「结果目录」为准):
1. **跑 `python "<本技能目录>/scripts/draft_rca.py" <结果目录>/rca_input.json`**:机械生成诊断骨架 `rca_draft.json`——所有"成立"节点已枚举成候选、根→叶路径与证据已预填,你**不需要也不允许**自己逐个节点翻找候选;
2. **写一份小裁决单** `<结果目录>/decisions.json`(一个候选一条,只写判定与理由,格式见 finalize_rca.py 文件头):逐条语义复核后给 `verdict`(confirmed/probable/excluded/undetermined),疑似补 confidence/caveats/blocked_at,排除必须给 reason;
3. **跑 `python "<本技能目录>/scripts/finalize_rca.py" <结果目录>/rca_draft.json <结果目录>/decisions.json -o <结果目录>/rca.json`**(有 `assets/tree/solutions.json` 时加 `--solutions`,再加 `--rca-input <结果目录>/rca_input.json` 抄 tree_issues)——几百行 rca.json 由代码机械拼装,**不要手写 rca.json**。合成器自带结构闸:候选漏裁决/确证路径带反证・冲突・存疑(祖先「数据不足」不拦,自动落 caveats)/排除无理由/有证据的塞待确认,都会响亮拒收——**报错就改裁决单重跑,合成成功即为最终交付,无需再跑校验**。
**每轮运行有自己独立新建的结果目录 `result-<运行号>/`,里面只有本轮的新 `rca_input.json`**——基于它产出 `rca.json` 即可,不会有过期 rca.json 干扰,也别去同级其它 `result-*`(历史轮次)里翻旧的当本轮答案。

> 结果目录已由 runner 建好——**直接往里写 `rca.json`,别再 `mkdir`**。Windows 路径用正斜杠 `/`,**勿以反斜杠结尾**(带引号路径写成 `"...\"` 会让 shell 一直等闭合引号而卡住)。

诊断链路的最后一步:把"各指标已经解析好的事实"和"故障子树"放在一起,判定根因。**本技能与指标种类无关**——今天是这几个、明天换成任意新指标,法则都一样。

## 上游喂给你什么(输入契约)
通常由 `cs-scot-execute` 汇总在本轮结果目录的 `rca_input.json` 里:
- **`fault_tree_md`**:故障子树正文(`#/##/###` 层级 + 条件)。**人工编写,可能不规整。** —— 或:
- **`fault_tree`(压缩形态)**:`pruned_nodes`(只含相关节点,每个把事实挂在 `facts` 里 + `condition`/`combine`/`pass_through`/`node_id`),另带 `tree_issues`(覆盖报告)、`unmapped_facts`、**`uncovered_values`(判别列里没被绑定认领的取值+条数 → 据此把漏绑的记录归到保留的"非典型/其他"兜底节点报出,别漏诊)**。两种形态法则一样;`pass_through` 节点不阻断路径;`node_id` 权威、别造不存在的节点。
- **`indicator_results`**(完整形态时):dict,键是指标名(**任意、不固定**),值是该指标已解析好的**事实**(**只有数据、没有判断**):各字段/项的真实分布、数值摘要或取值。
  - 有的指标给的是**定义/规则**(某量怎么算、阈值多少),**不是实测值**。**定义不是测量。**
  - **解析端不下判断、也不替你做匹配;判断全是你的活。**
- **`missing_indicators`**(可选,两种形态都可能带):本轮**整个数据源没提供**(execute 部分数据运行,
  解析步骤被跳过)的源名 → 原因。这些源绑定的判据一律「数据不足」——**既未证实也未证伪,别当"不成立/已排除"**;
  最终结论要注明缺口(相关候选进 `probable_causes`/`undetermined`,`blocked_at` 写清缺哪个源)。
- **`knowledge`**(可选):业务同事手写的外挂知识条目(已按当前分支筛过)。**是判读口径不是事实**:
  "怎么查/怎么解读/什么算正常"照它办(引用时写知识标题留痕);但**不能拿知识内容顶替实测值**,
  成立仍要数据里查到的事实。详见 rca_rules.md「输入」。

## 你要做什么(一个通用法则,不分指标)
遍历子树,对**每条判断条件**:
1. 看清它要的是**哪个量/字段/取值**(记作 X);
2. 到 `indicator_results` 找 X 的**实际值**:找到实测值 → 代入算"成立/不成立";没找到(没这个字段 / 只有定义没有实测值 / 这次没提供该数据)→ "**数据不足**";
3. 回溯到根 → 输出根因 + 逐节点判断依据。

详细规则见 `references/rca_rules.md`(**务必先读**)。

**三条铁律(最重要)**:
1. **只用真实事实,绝不顶替**:`actual` 逐字引用事实里的真实值;禁止引入事实里没有的数字;**条件要 X 就不能拿相关的 Y 算个数顶成"X 成立"**("有定义/有旁证"≠"成立");**精确匹配**(差一个字符即没命中)。
2. **要 X 却拿不到 X 的实测值 → 该条件"数据不足"**,不得当成立或不成立。
3. **四档分流**(详见 rca_rules.md):候选自身成立、路径无不成立/冲突 → **确证根因**`rca_result`(**祖先的「数据不足」不拦确证**——查不了是零信息,不冒充反证,大类由子节点事实自下而上蕴含;finalize 自动在 caveats 留痕);路径有节点不成立 → **排除**;有反证/冲突要权衡、或候选非叶子/子因未闭合 → **疑似**`probable_causes`(带 confidence + caveat,**别凑路径、别造节点**);其余 → `undetermined`。**`rca_result` 为 `[]` 很正常(上游缺话统/信令时),强证据放疑似。**

> 聚合数据里常并存多种失败模式 → **每个有正向事实的不同叶子/失败模式都各自报一条(别过度合并、别只挑最强的一两条,尽量报全)**;确证的要完整证实、疑似的要标 caveat,去重 + 排序。**有"未覆盖取值"且树里有"非典型场景/其他"兜底节点的,归过去报一条 + 附原始特征码,别漏诊。**
> **口径一致**:文字总结必须和落盘 `rca.json` 一致——`rca_result` 是 `[]` 就**别**说"发现 N 条根因";疑似就叫疑似。

## 工作方式:骨架先行 → 小裁决单 → 机械合成
1. **`scripts/draft_rca.py`(必跑第一步)**:机械枚举候选(成立→确证/疑似候选,预填路径+证据+how;不成立→排除候选;数据不足→待确认骨架;成立+强反证并存→冲突条目)。**枚举是代码的活——实测让模型自己找候选,成立的节点会被整个忘掉。**
2. **你的产出只有裁决单**(每候选一条 verdict+理由,十几行),**不是整份 rca.json**——实测手写几百行 JSON 又慢又抄错。裁决时要看某节点更多细节,用 `scripts/rca_query.py` 抽查(`--node nX` / `--outline` / `--holding`)。
3. **`scripts/finalize_rca.py` 机械合成 rca.json**:evidence/路径逐字来自骨架,待确认骨架自动带出,解决方案自动点查;结构闸拒收违规裁决(见文件头)。
**别把整个 rca_input 读进上下文**(会超长报错),也别自己写脚本硬算 RCA、别绕过合成器手写 rca.json。
**禁止手写 `python -c` 去解析 rca_input/rca_draft/rca.json**——字段名靠猜(实测连猜三轮全落空)、
Windows 上 `open()` 不带 encoding 直接 GBK 报错,一轮诊断白烧十分钟;裁决所需信息骨架里**已全部预填**,
看细节只许用 `rca_query.py`(--outline / --node nX / --holding),看完直接写裁决单。

## 诚实性:靠合成器的结构闸,不靠事后校验
诚实性检查已内建在 finalize_rca 的合成过程里(候选一条不许漏裁决、确证闸=**候选自身成立**——候选是**最深成立节点**:叶子最好,**中间节点且下级无一成立也确证**(叶子因待定+子节点三态自动落 caveats,数据补齐后重跑可细化);祖先的「数据不足/不成立/冲突/存疑」一律不拦确证,但全部自动落 caveats 标出留痕(冲突的两边实测值在 evidence 该条目的 conflict_actual/conflict_how 里,报告要把矛盾点复述给人复核)、排除必须给 reason、有成立事实的候选不收待确认、evidence 逐字来自骨架改不了数字)——**合成成功即交付,不需要再跑 validate_rca**。(`scripts/validate_rca.py` 保留:辩论引擎路径与人工抽查仍可用。)

## 输出契约
```json
{
  "rca_result": [ {"Root_cause":"…","Fault_tree_path":["…"],"support":"…",
     "evidence_path":[{"node":"…","node_id":"…","condition":"<逐字>","actual":"<逐字引用事实;没有写'事实中无此值'>",
        "how":"<怎么判的人话:事实带 explain 就逐字抄,数字不许改写>","judgment":"成立/不成立/数据不足"}]} ],
  "probable_causes": [ {"Root_cause":"…","Fault_tree_path":["…"],"confidence":"high/medium/low",
     "blocked_at":"<卡点:反证/冲突/未闭合的子因>","caveats":"<有效样本量/空值比例/语义近似>","support":"<叶子证据>","evidence_path":[…]} ],
  "undetermined": [ {"Fault_tree_path":["…"],"blocked_at":"…","reason":"缺哪个量","observed":["…(仅观察,非根因)"]} ],
  "tree_issues": { "uncovered_condition_nodes":[…], "orphan_node_ids":[…] }
}
```
每条 evidence 把 **条件 + 实际值 + 判断** 写全。详细分档/字段见 `references/rca_rules.md`。

> **推荐解决方案**:产物 `tree/solutions.json` 存在时,定完根因后对 `rca_result`/`probable_causes`
> 报出的节点按 node_id 点查,条目加 `"recommend_solution"`(优先中文),文字汇报也带上——
> 只查报出的那几个节点,查不到不加、**绝不编方案**。详见 rca_rules.md 输出契约。

## 分工(重要)
- **解析端只把数据查清楚摆出来**(事实),**不下任何判断、不做故障树匹配**。
- **判断全在你这一步**:把真实值代入故障树条件 → 比较 → 成立/不成立;要 X 没 X 就数据不足;再做路径回溯、逐节点取证、处理子树的不规整。两边都不许编。
