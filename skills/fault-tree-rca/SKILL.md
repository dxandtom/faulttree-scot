# fault-tree-rca —— 综合根因分析

**本文件已加载,不要再次加载或调用本技能;"加载"≠"完成",真正产出根因 JSON 才算完成。** 现在立刻依据 `result/rca_input.json` 和下文规则产出根因、写到 `result/rca.json`。

诊断链路的最后一步:把"各指标已经解析好的结果"和"故障子树"放在一起,判定根因。

## 上游喂给你什么(输入契约)
通常由 `cs-scot-execute` 汇总在 `result/rca_input.json` 里:
- **`fault_tree_md`**:故障子树正文。`#/##/###` 表层级;每个标题下面跟着该节点的判断条件正文。**由人工编写,可能不规整、有跳跃或笔误。**
- **`indicator_results`**:dict,键是指标名(`kpi` / `chr` / 未来任意指标),值是该指标解析脚本输出的**事实 JSON**——**只有 `summary` / `field_stats` / `referenced`,没有任何判断**:
  - `field_stats`:各字段的分布(类别 top-N + 样例)/ 数值摘要;
  - `referenced`:故障树引用到的计数器/字段的**取值/计数**(`found`、`value`、`count`、`where`、`samples`、`definition`)。
  - **parser 只查数据、不下判断;"是否成立"全部由你来算。**

## 你要做什么
遍历子树,对**每条判断条件**:从 `indicator_results` 的 `referenced`/`field_stats` 取相关值 → 套用**故障树里的**阈值/比较/算术 → 算出成立/不成立 → 回溯到根 → 输出根因 + 判断依据。详细规则见 `references/rca_rules.md`(务必先读)。

**三条铁律(最重要)**:
1. **只用真实事实**:evidence 的 `actual` 逐字引用 parser 给的值/计数(如 `N.x = 60`、`RrcReject = 4/10`);**禁止**引入 parser 没给过的计数器/数字,**不自行编数、不重算不存在的量**。
2. **取不到所需值**(`found:false` 或事实里没有)→ 该条件**数据不足 / 未判定**,不得当成立或不成立;**不拿 `field_stats` 的分布数硬当某条件命中**。
3. 一条路径算根因,要求**路径上每个带判断条件的节点都"成立"**;**没有完全证实的路径就如实输出"未找到充分证据的根因"(`[]` + undetermined),绝不硬凑编值编根因**。

> 聚合数据里可能并存多种失败模式 → 多根因合理,但**每个都要完整证实**,并**去重 + 按支持度排序**。

## 输出契约
```json
[
  {"Root_cause":"根因节点名称",
   "Fault_tree_path":["父节点1","父节点2","根因节点"],
   "evidence_path":[
     {"node":"父节点1","condition":"<逐字判断条件>","actual":"<实际数值>","judgment":"<代入比较 → 成立/不成立>"},
     {"node":"根因节点","condition":"...","actual":"...","judgment":"..."}
   ]}
]
```
每条 evidence 必须把 **规则(`condition`,逐字取自故障树)+ 实际值(`actual`,逐字引用 parser 事实)+ 怎么判断与结论(`judgment`,你现在代入比较算出)** 写清楚,**不能只写一句裸条件**。

## 分工(重要)
- **parser 只把数据查清楚摆出来**(事实:`summary` / `field_stats` / `referenced`),**不下任何判断**。
- **判断全在你这一步**:把 parser 的真实值代入故障树条件 → 比较 → 算成立/不成立;再做路径回溯、逐节点取证、处理子树的不规整。两边都不许编。
