# fault-tree-rca —— 综合根因分析

诊断链路的最后一步:把"各指标已经解析好的结果"和"故障子树"放在一起,判定根因。

## 上游喂给你什么(输入契约)
通常由 `scot-execute` 汇总在 `result/rca_input.json` 里:
- **`fault_tree_md`**:故障子树正文。`#/##/###` 表层级;每个标题下面跟着该节点的判断条件正文(计数器算术、阈值、占比等)。**由人工编写,可能不规整、有跳跃或笔误。**
- **`indicator_results`**:dict,键是指标名(`kpi` / `chr` / 未来任意指标),值是该指标解析脚本(`script` 步骤)输出的 JSON。其中 **`conditions`** 数组已给出每条故障树判断条件的命中结果:`{expr, values, hit}`(脚本已确定性算好)。

## 你要做什么
遍历子树,综合各指标的 `conditions`,判定哪些故障路径成立 → 回溯到根 → 输出根因 + 逐字依据。**所有**成立的路径都要输出。详细规则见 `references/rca_rules.md`(尤其 evidence_path 标准,务必先读)。

## 输出契约
```json
[
  {"Root_cause":"根因节点名称",
   "Fault_tree_path":["父节点1","父节点2","根因节点"],
   "evidence_path":["对应父节点1的逐字依据","对应父节点2的逐字依据","对应根因节点的逐字依据"]}
]
```

## 分工(重要)
- 数值的加减/比较/计数/占比等**已由解析脚本算好**(在 `conditions` 里),**直接采用,不要重算**。
- 你负责模型擅长的部分:组合判断、路径回溯、逐字取证、处理子树的不规整。
