# cs-scot-eval —— 诊断准确率评测(合成故障注入)

**本文件是操作手册,已加载,不要再次加载。** 任务:对一套**自带标准答案**的合成场景,跑出诊断准确率表。

## 为什么这么测
真实故障没人标过"正确根因",所以准确率没法直接测。办法是**自己造**:亲手埋一个根因、造让它成立的数据,正确答案我自己知道 → 跑完一比就是准确率。

场景在 **`suite_real/`**:在 **`trees/` 下多棵不同大小的树**(脱敏真实树 + 它的子树 + 合成树,~27/44/95/178/320 节点)上注入根因——埋在深处,每个节点叠**真实业务判据 + 具体数值**(成功率/错误码占比/告警/信令/占比…),周围撒"事实成立但路径断了"的诱饵 + 一堆不成立/数据不足噪声。剪枝后局部子树 ~10~25 节点,模型必须**在大树里追出唯一闭合路径**。多规模 → 出"准确率 vs 树大小"。

**关键:事实里【不带 `predicate_satisfied`】**,只给实际值 + 判据(带阈值),**逼模型拿值自己判条件成立/不成立**,不是读字面布尔。(真实生产输入是带 predicate 的,这里刻意抽掉做更硬的考。)**Mode A**:跳过模型绑定 → 隔离测 RCA 完整推理:**判条件 + 大树导航(闭合路径/AND-OR/档位)+ 抗诱饵 + 诚实**。

> **考题已冻结提交,本地不要重新生成**(出题方=可信侧,答题方=你本地模型,防止自出自答找便宜路)。
> `suite_real/<场景>/rca_input.json` = **答题模型唯一该读的**;`suite_real/_answers/` = **答案区,做 RCA 时别读**,只给打分器。

## 两步跑法(主:真实大树 `suite_real`,考题已预置)

### 步骤 1:逐场景做 RCA(**这一步是模型判断,正是被打分的对象**)
对 `suite_real/` 下**每个**场景(`_answers/` 不是场景),用 **fault-tree-rca** 技能读它的 `rca_input.json` 做根因判断,把结果按该技能的契约写到**同目录** `rca.json`。
> 别去翻 `_answers/`——那是作弊;就当普通一次 RCA,凭 `rca_input.json` 里的事实(局部子树)判。

### 步骤 2:打分出表(确定性)
```bash
python "<本目录>/scripts/score_accuracy.py" --suite "<本目录>/suite_real" -o "<本目录>/accuracy_report.txt"
```
对每个场景的 `rca.json` 比对标准答案,出四项:
- **命中**:埋的根因有没有落在【应在的档位】(确证→`rca_result`;疑似→`probable_causes`;无因类→不报确证);
- **档位准**:没把"该疑似的"报成确证、没漏档;
- **无假阳**:没把"路径断了的干扰叶子"等 `must_not_report` 节点报成根因;
- **诚实**:对真值查"伪造成立"——凡判"成立"的节点必须确实是埋下的 `hold` 节点;在 fail/数据不足 节点上判成立 = 不诚实。
综合 = 四项全过;聚合成准确率 % + **按树规模分档**。

## 自测打分链路(可选,不测模型)
```bash
python "<本目录>/scripts/score_accuracy.py" --suite "<本目录>/suite_real" --use-reference
```
用每个场景的 `reference_rca.json`(满分参考)当输入,应出 **100%**——证明注入+剪枝+打分链路本身没毛病。

## 换树 / 扩充场景(维护用,平时不跑;改完要重新提交冻结)
- **加树/换规模**:`make_trees.py` 从真实树切子树 + 生成合成树到 `trees/`(改 `SUBTREES`/`SYNTH` 调规模);要加你自己的脱敏真实树,丢进 `trees/` 即可(只需拓扑,condition 可 null)。
- **重生成考题**:`inject_on_tree.py` 遍历 `trees/` 每棵树自动出 6 类场景到 `suite_real/`(确定性),改完重新提交冻结。
- **加业务判据**:在 `inject_on_tree.py` 的 `PERSONAS` 加/改人设(判据文本 + hold/fail/insuf 事实值)→ 判据更丰富。

## 注意(写进汇报必须说清)
- 这是**【受控合成故障注入】下的 RCA 大树推理稳健性**:拿实际值判条件 + 在几十~几百节点里追闭合路径 + 抗诱饵 + 诚实,是**必要不充分**——连埋的因都找不对则现网必不行,找对了≠现网准确率(真实故障更脏)。口径写"受控合成下的诊断推理准确率",别写成"真实准确率"。
- 判据/数值是**可信侧合成的真实业务样例**(非现网实测);考题由可信侧出、本地只答题(出题≠答题)。**不**测 data→事实的绑定环节(那要金标准绑定,专家未定)。
- 与 `cs-scot-benchmark` 互补:benchmark 测 省/稳/可复现/诚实/转换/内核回归(**无** ground truth),本技能测**准确率**(**有** ground truth)。
- Python 3.11;路径有空格/中文务必加引号。
