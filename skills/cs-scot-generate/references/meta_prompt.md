# 元提示词:为某个指标生成「解析脚本生成提示词」

## 你的角色与三级链的层级(先看清)
你是提示词工程师。给你(指标名 + 故障子树 + 该指标数据的真实表头/样例),你要产出**一份「解析脚本生成提示词」**。

三级链:`元提示词(本文件,第1级)→ 你产出的 codegen 提示词(第2级)→ 解析脚本(第3级)`。
你做第 2 级。**你产出的提示词是直接对"写脚本的 LLM"说话的**,口吻是
"**请写一个解析 XX 数据的 Python 脚本,满足……**";**不要**把本元提示词"你是提示词工程师、请产出一份提示词"的口吻复制下去。

## 输入(调用时注入)
1. 指标名。
2. 故障子树(md)。
3. **该指标数据的真实表头/结构 + 一小段真实样例**(务必拿真实数据看)。

## 你产出的「解析脚本生成提示词」必须包含下列各条

### 〇、最高铁律:真实,绝不编造
- **严禁发明**故障树里没有的阈值/条件/指标;**严禁**用相近字段顶替、用粗略 substring 凑数后给 true/false。
- **算不出来就如实说**:见下面"两类 hit"的 `null` 情形。
- 宁可报"未知",也不要假阳性。"查不到"有时正说明数据传错/不全——这本身就是有用结论。

### 一、数据驱动地提取真实信息(不要把字段写死在提示词/脚本里)
脚本要**自动发现**数据里实际存在的字段/结构并遍历,提取**与本场景故障子树相关**的真实信息;不要依赖提示词逐个枚举字段。按数据形态:
- **表格型**(首行表头 + 多列,如 CHR):遍历表头;对故障树条件引用到的字段做计数/分布/区间等统计。
- **目录型**(单列、每行一段 JSON,字段可**异构**,如 kpiTree:有的含 `formula/kpiIndex/absExceptionThreshold/unit`,有的只有 `category/name`):
  - 逐行剥 CSV 外层引号 + `json.loads`(兼容缺字段、异构、非法行);
  - 用 `parentId→id` **建树**,理清 KPI 父子关系;
  - **遍历每行的所有键**,提取相关 KPI 的 `name/kpiIndex/formula/absExceptionThreshold/unit/definition` 等真实字段;
  - 把故障树用到的计数器(`N.xxx`/`L.xxx`)与目录**交叉引用**:被哪些 KPI 的 `formula` 用到、是否覆盖、异常阈值多少(参考"覆盖率 / counter↔KPI"思路)。
- 只围绕**子树相关**的东西;**不堆无关字段、不转储大量原始记录**。

### 二、两类条件的 hit(关键:区分"能判定"和"只有定义/上下文")
- **数据里有该量的实测值** → 用代码算:`hit: true/false` + `actual` + `samples`。
- **没有实测值、但有相关定义/阈值/覆盖**(典型:kpiTree 是 KPI 目录,有公式和异常阈值、没有实测计数值)→ `hit: null` + 把提取到的**定义/异常阈值/覆盖**放进该条 `context`,并注明"无实测值,未判定"。
  - 即:**不是"直接 null 什么都不给",而是把目录里真有的信息如实提取出来,只是不下成立/不成立的结论**。
- 完全缺字段、无法提取也无相关信息 → `hit: null` + `status:"数据不足:缺 <字段>"`。

### 三、映射到真实字段(别猜列名)
- 先读真实表头/JSON 键,把每条故障树条件**精确对应**到真实的列/字段/取值;**严禁硬编码猜测的列名**。
- 话统计数器在事件类数据(如 CHR)里**可能**体现为某字段取值(如某 `InnerCause`)。**只有能从真实样例确认对应时才映射**;否则按"两类 hit"标 `null`(可带 context)。
- 需要按 `CALLID` 等跨记录关联的就**真的关联**;关联所需记录/字段缺失 → `null`。

### 四、自包含 + 形态自动判别
- 内联一个读取函数,**自动判别**表格型 / 单列 JSON 型,兼容 xlsx + 编码自动检测;**不要 import 任何本仓自定义模块**。

### 五、留取证痕迹(让人能抽查)
每条 condition 带:`basis`(用了哪一列/字段/取值判断的)+ `samples`(命中的 3~5 个标识,如 `CallID`/行号),供人 grep 原始数据核对。

### 六、输出 JSON 结构
- `summary`:精简但含有用的提取结果(如 KPI 树规模、计数器覆盖率、关键字段分布)。
- `conditions`:数组,每条 = `expr / values / actual / judgment / hit(true|false|null) / basis / samples /(可选)context /(可选)status`。

### 七、工程要求 + 自检
- Python 3.11;CLI 参数:数据文件(位置)、`-o/--output`;**自包含**;异常处理;中文注释;可直接运行(xlsx 需 openpyxl)。
- 跑完产出**合法 JSON**;`hit/judgment` 与数据一致;**算不了的必须是 `null`(可带 context),绝不编 true/false**。

## 输出格式
**只输出**那份「解析脚本生成提示词」的 Markdown 正文(对"写脚本的 LLM"说话的口吻),不要额外解释或代码块包裹。
