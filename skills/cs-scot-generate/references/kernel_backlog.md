# 判别内核总览 + 待扩展清单(带证据)

把"故障树的判断条件"归纳成**可机械执行的判别原语**。本文件两件事:
1. **已实现的 A–J 内核**(`condition_kernels.py`,execute 只跑、不改统计;有 `kernel_selftest.py` 回归护栏);
2. **已识别、暂未落代码的判别**(K–O):受限于**当前场景无对应数据**或**语义未定义**,按项目铁律"每个内核都要能用真实数据验证"——**先记证据、不写投机代码**,等对应场景带数据上线即照此建并当场验证。

> 统计口径:共识别 **16 种判别逻辑** = 已实现 **10**(A–J)+ 待扩展 **6**(K–O,其中 O 已解锁,见下)。
> A–J 是 10 个**标签**、约 7 个**底层原语**(G=C、F≈C、I.row_threshold≈A.count_rows);标签对齐故障树措辞、便于选型,原语共享、不漂移。
> 横切能力(格式契约 v2 起,详见 binding schema):`filter` 行级预过滤(EAV 窄表选量,作用于 A/B/C/F/G/I;
> E 内建单子句 filter 语义独立、D/H 顶层 filter 响亮拒绝)+ 空表/filter 命中 0 行 → 一律「数据不足」不当排除。

## 二、已识别、待扩展的判别(K–O)——缺数据 / 语义未定,暂不落代码

判定每条用同一把尺子:**原语是否真新 · 当前数据有无立足点 · 失败方向是否安全**。证据来自对真实故障树原文的扫描与本地数据 `analyzer.py --lean` 的概览(2026-06 取证)。

| 代号 | 名称 | 判别逻辑 | 树上典型原话 | 为何暂不落代码(证据) |
|---|---|---|---|---|
| **K** | 连续周期/持续性 | 连续 N 个周期都越线(游程);含"每日累计/次数"的时段分桶聚合 | `连续4个话统周期 VS.MeanRTWP > -85`;`每天累计告警时间 > 300s` | 当前 KPIResult **不含**这些计数器;且"周期/分组键/缺期处理"= **分析单元**问题,未拍板。形状够(KPI 为小时粒度、按 cellName 排序),数据缺 |
| **L** | 趋势/变化率 | 相对变化 `(后−前)/前` 与阈值比较 | `(refarming后掉话率 − refarming前掉话率)/故障前掉话率 > 15%` | 树**未定义**"前/后"锚点;且这些 GSM 计数器(L9506/CM33…)不在当前数据。属吞吐/话务场景,非当前 SA 接入 |
| **L′** | 事件对时序 | 同会话内 A 消息后 T 内是否出现 B(最近配对) | `Ciphering Mode Command 与 Complete 间隔 > 0.564s`;`Reloc ACK 后 1s 内收到 IU RELEASE` | **数据形状已具备**(CHR/信令为毫秒级、带 CallID、按时间排序)→ 未来最佳候选;但条件属 CSFB 时延场景,当前数据里无此场景 |
| **M** | 版本比较 | 版本号有序比较(≥/<、区间、通配符段) | `基站版本 20BSPC180 及以后`;`RNC 版本在 R16SPC650 之前`;`ProgVer 大于 5.*.09.11` | **格式异构**(实测 ≥8 种:V-R-C-SPC / 20A / R16SPC650 / 5.*.09.11 通配 / V900R019**ENG**…),单一比较器会**静默错排**;唯一立足点 `Version` 列只有单值,无法验排序。**注:"包含/列表/精确"那部分已由 C 覆盖**,只剩"及以后/之前/区间"是真新且有风险 |
| **N** | 跨组对比 | 本对象指标 vs 同组其他对象的统计量(基线) | `本小区 VS.MeanTCP 比同覆盖其他载波大 3dB 以上` | 缺"同覆盖组"的分组定义(需配置);当前数据无对应列。属覆盖/质量场景 |
| **O** | 告警存在性 | 告警日志是否出现指定告警码(任一) | `存在 ALM-26106 单板时钟输入异常告警` | **✅ 已解锁**(不需新内核,逻辑=C/G 的 contains+require):数通 dblg/log 的 `Summary` 告警码列已接入,C/G 直绑(见 `datacom_log_adapter.md` 第五节) |

## 三、各项的"解锁条件"(供专家/数据侧拍板备料)

- **L(变化率,杠杆最大)**:只需一句话——**"前/后"两段数据是发货时就分好标签的两份(/两列/两页签),还是一张表要按故障时刻自己切?** 若是前者 → 退化为 B 类比值(给 B 加 `ratio` scope 即可),6+ 条一起解锁;若是后者 → 才真卡分析单元。
- **K / L′ / N**:都依赖"一次分析读多少行 / 什么粒度 / 分组键是谁"(分析单元)。需要:周期粒度与分组键(K)、配对键与时间精度(L′)、同组的分组配置来源(N)。**数据形状已知**(见上),缺的是语义定义。
- **M(版本)**:确认 ①是否值得为它配一套 fixture 去扛"静默错排"风险;②树里是否**总在同一种格式内**比较(则内核可按"格式方案"参数化,而非自动识别)。便宜的 60%(包含/列表/精确)现在用 C 就能做。
- **O(告警)**:✅ 已解锁——数通 dblg/log 告警日志(`Summary` 码值列)接入后即按预案用 C/G 绑
  `contains=[告警码], require=1`,绑法与坑见 `datacom_log_adapter.md`。

## 四、维护约定

- **新增内核 = 同时新增 `kernel_selftest.py` 用例**(成立/不成立/数据不足/边界各覆盖);无真实数据可验的内核**不进主干**。
- 新增判别若改变产物结构 → bump `assemble_scenario.py` 的 `PRODUCT_FORMAT_VERSION`(与 `runner.py` 的 `EXPECTED_PRODUCT_FORMAT` 成对)。
- 本表随取证更新;"树上原话"务必逐字引用、注明出处,不得推断或编造。
