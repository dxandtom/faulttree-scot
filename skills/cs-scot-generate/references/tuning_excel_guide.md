# 调优表使用说明(给业务同事)

你手里有一张 `xxx.tuning.xlsx`(调优表)。**故障树长什么样、每个节点怎么自动检查,全由这张表说了算**。
你改这张表 → 跑一条命令 → 诊断技能就按你改的来。不用会编程。

---

## 一、这张表怎么读

**一行 = 故障树上的一个节点**。上面的行是上级,下面缩进到更深列的行是它的下级(和原始故障树 Excel 一个读法)。

| 列 | 是什么 | 你能不能改 |
|---|---|---|
| `node_id` | 节点的身份证号(n77 这种) | **绝对不要改、不要复制**;新加的行**留空** |
| `L2(Chinese)`、`L3(Chinese)`… | 各层节点名字 | 可改(改名) |
| `判据:xxx` | 这个节点的判断条件(人话描述) | 可改 |
| `绑定:config`、`绑定:log`… | 告诉电脑**怎么自动检查**这个判据(每个数据源一列) | 可改,照第四节的模板 |
| `Recommend Solution(Chinese/English)` | 诊断出根因时随结论输出的解决方案 | 可改 |
| `meta(勿改)` | 系统信息 | **别动** |

---

## 二、三条铁规(先记住再动手)

1. **node_id 不改、不复制,新行留空**——系统会自动编号;
2. **绑定格里只用英文标点**:引号必须是 `"`(不是 " ”),逗号是 `,`,括号是 `[ ]` `{ }`;
3. **改完必跑检查命令**(见第六节)——它会用人话告诉你哪行改坏了,照提示改就行。**它没报错之前,你的修改还没生效。**

---

## 三、改树

**加一个节点**:
1. 找到它的上级那一行,在上级的"块"里(它下级们所在的位置)插入一行;
2. 把上级各层的名字**照抄**到对应列;
3. 在它自己那一层的列里写新节点的名字;
4. `node_id` **留空**;
5. 写上判据(人话),能写绑定就照模板写,不会写就留空(留空 = 这个节点暂时不会被自动检查,系统会提示"未覆盖")。

**删一个节点**:删掉它那一行,**连同它下面所有以它为上级的行一起删**。

**改名/改判据/改解决方案**:直接改格子里的文字。

---

## 四、改绑定(复制模板,改【】里的内容)

绑定 = 告诉电脑"去哪个数据、看哪一列、找什么"。五个模板覆盖绝大多数情况,**整段复制到绑定格里,只改【】的部分**:

**模板 1:日志/告警里出现某个字样,就算命中**
```json
{"class": "G", "column": "【列名,如 Summary】", "contains": ["【要找的告警名/关键字】"], "mapping_reason": "【一句话:为什么这样查】"}
```
> 关键字要用**独一无二的告警名/错误码**(如 hwBfdSessDown),别用"CRC:""LLDP"这种到处都有的词——正常日志也有的词会误报。

**模板 2:配置里有某条配置**
```json
{"class": "G", "column": "【配置列,如 level2】", "contains": ["【配置命令关键字】"], "mapping_reason": "【…】"}
```

**模板 3:配置里没有某条配置(缺了才算故障)**
```json
{"class": "G", "column": "【配置列,如 level2】", "contains": ["【应该有却没有的配置】"], "absent": true, "mapping_reason": "【…】"}
```
> "配了A但没配B"就是模板 2 + 模板 3 组合:
> ```json
> {"class": "D", "combine": "AND", "sub": [
>   {"class": "G", "column": "level2", "contains": ["【A】"]},
>   {"class": "G", "column": "level2", "contains": ["【B】"], "absent": true}],
>  "mapping_reason": "【…】"}
> ```

**模板 4:某个数值超过/低于门限**
```json
{"class": "A", "column": "【数值列名】", "op": ">", "threshold": 【数字,不带引号】, "scope": "count_rows", "require": 1, "mapping_reason": "【…】"}
```
> `op` 可换 `<` `>=` `<=`;`require` 是"至少几行满足才算"。

**模板 5:这个数据源查不了这条判据**
```json
{"decision": "insufficient_data", "mapping_reason": "【为什么查不了,如:需要 display 命令输出,本源是告警日志】"}
```

其它说明:
- 一个节点可以在**多个数据源列**都有绑定(多个源各查各的,很正常);
- 同一格要放两条绑定时,用方括号包起来:`[{...}, {...}]`;
- 把某格清空 = 删掉这条绑定;
- **新增一个数据源**:在表头行加一列,名字写 `绑定:新源名`(如 `绑定:diag`),下面照常填绑定——系统会自动把新数据源接进流程。

---

## 五、判断"绑定写得好不好"的一个土办法

问自己:**"正常的、没故障的设备,这条绑定会不会也命中?"**
会 → 这个关键字太宽了,换更专属的告警名/错误码。诊断的本事就在"故障时命中、正常时不命中"。

---

## 六、改完之后(必做)

在技能目录下运行(把路径换成你的):

```bash
python assets/scripts/import_tree_excel.py --out assets
```

- **报错**:它会按 Excel 行号用人话指出问题(引号不对/上级没照抄/id 重复…),照提示改完重跑。报错时**什么都没写入**,不用担心改坏;
- **成功**:它会打印"变更摘要"(加了什么节点、改了哪些绑定)——核对一眼是不是你想改的;
- 然后用真实数据试跑一次诊断,确认效果。

---

## 七、常见报错对照

| 报错里出现 | 原因 | 怎么办 |
|---|---|---|
| 中文引号 | 输入法打出了 " " ' ' | 系统已自动纠正,下次切英文标点 |
| JSON 解析失败 | 少逗号/少括号/引号不配对 | 对照第四节模板逐字检查那一格 |
| node_id 重复 | 新行复制了别行的 id | 新行 id 清空 |
| 上级……对不上 | 新行插错位置,或上级名字没照抄 | 挪到上级的块里,把上级各层名字抄对 |
| class 不认识 | 绑定里 class 写错 | 用第四节的模板,别自造写法 |
