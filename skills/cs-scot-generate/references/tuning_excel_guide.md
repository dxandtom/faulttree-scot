# 调优表使用说明(给业务同事)

你手里有一张 `xxx.tuning.xlsx`(调优表)。**故障树长什么样、每个节点怎么自动检查,全由这张表说了算**。
你改这张表 → 跑一条命令 → 诊断技能就按你改的来。不用会编程。

---

## 一、这张表怎么读

**一行 = 故障树上的一个节点**。上面的行是上级,下面缩进到更深列的行是它的下级(和原始故障树 Excel 一个读法)。

| 列 | 是什么 | 你能不能改 |
|---|---|---|
| `node_id` | 节点的身份证号(n77 这种) | **绝对不要改、不要复制**;新加的行**留空** |
| `L2(Chinese)`、`L3(Chinese)`… | 各层节点名字 | 可改(改名) |
| `判据:xxx` | 这个节点的判断条件(人话描述) | 可改 |
| `判据:原文` | 老格式故障树的判据整段放这一列(和上面二选一,别两边都填) | 可改 |
| `绑定:config`、`绑定:log`… | 告诉电脑**怎么自动检查**这个判据(每个数据源一列) | 可改,照第四节的模板 |
| `Recommend Solution(Chinese/English)` | 诊断出根因时随结论输出的解决方案 | 可改 |
| `meta(勿改)` | 系统信息 | **别动** |

---

## 二、三条铁规(先记住再动手)

1. **node_id 不改、不复制,新行留空**——系统会自动编号;
2. **绑定格里只用英文标点**:引号必须是 `"`(不是 " ”),逗号是 `,`,括号是 `[ ]` `{ }`;
3. **改完必跑检查命令**(见第六节)——它会用人话告诉你哪行改坏了,照提示改就行。**它没报错之前,你的修改还没生效。**

---

## 三、改树

**加一个节点**:
1. 找到它的上级那一行,在上级的"块"里(它下级们所在的位置)插入一行;
2. 把上级各层的名字**照抄**到对应列;
3. 在它自己那一层的列里写新节点的名字;
4. `node_id` **留空**;
5. 写上判据(人话),能写绑定就照模板写,不会写就留空(留空 = 这个节点暂时不会被自动检查,系统会提示"未覆盖")。

**删一个节点**:删掉它那一行,**连同它下面所有以它为上级的行一起删**。

**改名/改判据/改解决方案**:直接改格子里的文字。

---

## 四、改绑定(复制模板,改【】里的内容)

绑定 = 告诉电脑"去哪个数据、看哪一列、找什么"。下面的模板覆盖绝大多数情况,**整段复制到绑定格里,只改【】的部分**:

**模板 1:日志/告警里出现某个字样,就算命中**
```json
{"class": "G", "column": "【列名,如 Summary】", "contains": ["【要找的告警名/关键字】"], "mapping_reason": "【一句话:为什么这样查】"}
```
> 关键字要用**独一无二的告警名/错误码**(如 hwBfdSessDown),别用"CRC:""LLDP"这种到处都有的词——正常日志也有的词会误报。

**模板 2:配置里有某条配置**
```json
{"class": "G", "column": "【配置列,如 level2】", "contains": ["【配置命令关键字】"], "mapping_reason": "【…】"}
```

**模板 3:配置里没有某条配置(缺了才算故障)**
```json
{"class": "G", "column": "【配置列,如 level2】", "contains": ["【应该有却没有的配置】"], "absent": true, "mapping_reason": "【…】"}
```
> "配了A但没配B"就是模板 2 + 模板 3 组合:
> ```json
> {"class": "D", "combine": "AND", "sub": [
>   {"class": "G", "column": "level2", "contains": ["【A】"]},
>   {"class": "G", "column": "level2", "contains": ["【B】"], "absent": true}],
>  "mapping_reason": "【…】"}
> ```

**模板 4:某个数值超过/低于门限**
```json
{"class": "A", "column": "【数值列名】", "op": ">", "threshold": 【数字,不带引号】, "scope": "count_rows", "require": 1, "mapping_reason": "【…】"}
```
> `op` 可换 `<` `>=` `<=`;`require` 是"至少几行满足才算"。

**模板 5:这个数据源查不了这条判据**
```json
{"decision": "insufficient_data", "mapping_reason": "【为什么查不了,如:需要 display 命令输出,本源是告警日志】"}
```

**模板 6:必须发生在同一个接口/同一个对象上才算**
比如"同一个接口既有 A 又缺 B 才是故障"——不加分组的话,A 在 1 号接口、B 在 2 号接口也会被误判成立。
加一句 `"group_by": "接口所在的列名"` 就按接口分组、逐个接口判:
```json
{"class": "D", "combine": "AND", "group_by": "【接口/对象所在列,如 level1】", "sub": [
  {"class": "G", "column": "【内容列,如 level2】", "contains": ["【要有的内容A】"]},
  {"class": "G", "column": "【内容列,如 level2】", "contains": ["【要没有的内容B】"], "absent": true}],
 "mapping_reason": "【同一接口配了A但没配B才成立】"}
```

**模板 7:值藏在一格文字里,要先抠出来再比**
比如某列的格子长这样:`利用率:83%,速率:1G`,判据要"利用率>70"。加一句 `extract` 告诉电脑抠哪段:
```json
{"class": "A", "column": "【列名】", "extract": {"kv": "【值前面的名字,如 利用率】"}, "op": ">", "threshold": 【数字】, "scope": "count_rows", "require": 1, "mapping_reason": "【…】"}
```
> `"kv": "利用率"` 的意思是:找「利用率:」「利用率=」后面跟的那个值。抠出来的是文字也行——
> 把模板 1 加上同样的 `extract`,就是"抠出值再比对文字"(如抠出「状态」再看是不是 Down)。

**模板 8:本端和对端要一致(不一致才算故障)**
比如"两台设备的 IP 必须一致,不一致就是配置错"。数据里同一张表既有本端的行又有对端的行,
靠某一列区分谁是谁(比如 `Object` 列,本端带 `*` 号):
```json
{"class": "P", "side_column": "【区分本端/对端的列,如 Object】", "value_column": "【要比较的值所在列】", "fault_when": "not_equal", "mapping_reason": "【两侧该值不一致即故障】"}
```
> 查不到对端时,结果是"数据不足"(不是"没故障")。要比的值藏在一格文字里,同样可以加 `extract`。

其它说明:
- **有的节点的自动检查不在本表里**:需要"先查一处、再拿结果查另一处"的复杂检查(跨源绑定)由
  工程同事在别的文件里维护。导出调优表时系统会列出这些节点;你在表里**改这些节点的判据或删掉
  这些节点**时,请知会工程同事(导入时系统也会自动打印复核提醒,照着转告即可);
- 一个节点可以在**多个数据源列**都有绑定(多个源各查各的,很正常);
- 同一格要放两条绑定时,用方括号包起来:`[{...}, {...}]`;
- 把某格清空 = 删掉这条绑定;
- **新增一个数据源**:在表头行加一列,名字写 `绑定:新源名`(如 `绑定:diag`),下面照常填绑定——系统会自动把新数据源接进流程。

## 四点五、加"经验知识"改哪个文件

绑定管"怎么自动查",还有一类东西放不进绑定——**经验**:去哪查对端、什么现象属正常不算故障、
某型号某版本的已知问题。这些写进 **`assets/tree/knowledge.md`**(和调优表同目录),一条一段:

```
### 知识标题(一句话)
适用:分支关键词(如 M-LAG;写「通用」或不写这行 = 全场景生效)
正文:人话写清"去哪个数据、看哪列、怎么查、什么算正常"。
```

「适用」按**故障树节点名**匹配——诊断时只载入与当前分支相关的条目。改完存盘即生效,不用跑命令。
知识是给系统"指路和解读"用的;查证结论仍以数据为准,系统不会拿知识当证据。
(给工程同事:跨场景通用的经验建议同时沉淀到生成技能的**出厂知识库** `cs-scot-generate/knowledge.md`,
下个场景生成时自动带上。)

## 五、判断"绑定写得好不好"的一个土办法

问自己:**"正常的、没故障的设备,这条绑定会不会也命中?"**
会 → 这个关键字太宽了,换更专属的告警名/错误码。诊断的本事就在"故障时命中、正常时不命中"。

## 六、改完之后(必做)

在技能目录下运行(把路径换成你的):

```bash
python assets/scripts/import_tree_excel.py --out assets
```

- **报错**:它会按 Excel 行号用人话指出问题(引号不对/上级没照抄/id 重复…),照提示改完重跑。报错时**什么都没写入**,不用担心改坏;
- **成功**:它会打印"变更摘要"(加了什么节点、改了哪些绑定)——核对一眼是不是你想改的;
- 然后用真实数据试跑一次诊断,确认效果。

## 七、常见报错对照

| 报错里出现 | 原因 | 怎么办 |
|---|---|---|
| 中文引号 | 输入法打出了 " " ' ' | 系统已自动纠正,下次切英文标点 |
| JSON 解析失败 | 少逗号/少括号/引号不配对 | 对照第四节模板逐字检查那一格 |
| node_id 重复 | 新行复制了别行的 id | 新行 id 清空 |
| 上级……对不上 | 新行插错位置,或上级名字没照抄 | 挪到上级的块里,把上级各层名字抄对 |
| class 不认识 | 绑定里 class 写错 | 用第四节的模板,别自造写法 |
