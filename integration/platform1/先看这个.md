# 先看这个(5 分钟读完,再决定要不要读别的)

## 1. 这一层是干什么的

平台上有个"优化"按钮。点一下,平台把三样东西发给我们:

- 一张表:哪些故障树节点要改,每个节点的包在哪下载;
- 上一版 skill 的下载地址;
- 一个版本号。

我们要做的只有四步:**下载**表里的节点包和上一版 skill → **迁移**(把节点包装进 skill,这一步由技能自带的脚本完成)→ **打包**成新的 skill zip → **回调**平台(把 zip 发回去,平台自己存 OBS、改版本状态)。

`integration/platform1/` 就是围绕这四步的胶水代码。技能本身不在这里,在 `skills/`。以后换平台,这一层整体换掉,技能不动。

## 2. 只有三个文件要看

| 文件 | 干什么 | 行数 |
|---|---|---|
| `server.py` | 对外的 HTTP 服务。收平台请求,把表存下来,立刻回"已受理",后台起 driver.py | 60 |
| `driver.py` | 一单从头到尾:解表 → 下载 → 迁移 → 打包 → 回调。入口是函数 `run(req)` | 核心 |
| `downloader.py` | 下载。真跑时调平台给的 `download_fault_tree_artifact.py`;本机演示时从一个目录拷文件 | 150 |

其余文件一句话:`download_fault_tree_artifact.py` 是平台给的下载脚本,原样放着不改;`make_full_table.py`、`prepare_store.py` 是做实验的小工具;`demo.py` 是本机演示;`tests/` 是自动测试;两个 `.md` 分别给平台和给开发看;`obs_headers_config.json`、token 文件、`_runs/` 不进仓库。

## 3. 先跑一遍(不碰网络、不用模型,1 分钟)

```
python integration/platform1/demo.py
```

它会自己造样例(上一版 skill、一个节点包、一张表)、起一个假的平台回调接口、跑一单,最后告诉你日志、新版 zip、回调结果各在哪。看不懂代码没关系,先看它打印的过程。

## 4. 对照 run.log 读一单

演示跑完,`_runs/demo/run/run.log` 里按顺序会出现这几行,一行对应一步:

| 日志行开头 | 这一步在做什么 |
|---|---|
| `[回调地址]` | 决定做完往哪回调:请求里给的 → 环境变量 → 配置文件 |
| `[表]` | 读平台表,只取三样:节点路径(L1/L2/L3 中文名)、包名、包的下载地址 |
| `[下载]` | 逐个下载节点包,再下载上一版 skill。下完检查是不是合法 zip |
| `[skill]` | 解开上一版 skill |
| `[迁移]` | 调技能的迁移脚本,后面缩进的都是那个脚本的原样输出 |
| `对应表批量迁移汇总` | 迁移结果。`✓` 装进去了,`=` 没变跳过,`~` 只改了判据,`+` 新增节点,`✂` 删了节点,`✗` 失败 |
| `[模型]` | 只在有 `✗` 且装了 Claude Code 时出现:起一个无头会话修脚本,完了再跑一遍迁移做验证 |
| `[产物]` | 新版 skill zip 打好了 |
| `[回调]` | 发回平台,`responseCode` 为 `"0"` 就是成功 |
| `[停]` / `[失败回传]` | 这一单没做成。也会回调,回传没变化的上一版加一份失败报告,让平台的版本记录能闭环 |

## 5. 接到你们代码里要做的三件事

1. **收请求**:你们的服务收到 `versionId`、`excelFile`、`prevObjectkey`、`optimizeType` 四个字段,表存成文件。
2. **跑一单**:调 `driver.run(req)`,或者起子进程 `python driver.py --request req.json`。`req` 就是上面四个字段加表的路径(格式见 `request.example.json`)。下载、迁移、打包、回调它自己做完。
3. **放配置**:`obs_headers_config.json`(平台下载脚本的配置文件)里当前环境那一节加一个 `callback_url`,文件放在 driver.py 同目录。

不想用我们的 `server.py` 就只做第 1 和第 3 件。`driver.py` 不依赖 FastAPI,只依赖标准库和平台的下载脚本。

## 6. driver 里两处调用技能(要改逻辑先看这里)

- **机械**:`subprocess` 跑 `migrate_fault_check.py --package <包目录> --product <skill 产物目录> --auto --map <表> --map-mode all|multi`。树的增删、判据同步、跳过没变的包,全在这个脚本里;driver 只负责把文件摆到位、传参、读输出。
- **模型**:机械迁移有失败项时,起 `claude -p "<任务>"` 无头会话让它改脚本,完了再跑一遍机械迁移做验证。机器上没装 `claude` 就自动跳过这一步。
