# 平台1 联调接入代码 交接说明

**第一次接触先读同目录的 `先看这个.md`,再跑一遍 `demo.py`,然后再回来看本文。**

代码位置:`integration/platform1/`。这一层是**工装**,不是技能:技能(`skills/` 下那几个)只处理本地文件,
下载、回调、版本状态这些平台概念全部停在这一层。上平台2 时这一层可以整体换掉,技能不动。

## 2. 一句话链路

```
平台点优化 → POST /optimize(versionId + excelFile + prevObjectkey + optimizeType)
  → server.py 立刻回 {"result":"success"},后台起 driver.py 子进程
  → driver:解表 → 下载节点 zip 与上一版 skill → 解包 → 调迁移脚本 → 有失败项起模型档 → 复跑迁移
  → 打包新版 skill zip → POST 回调(versionId + skillFile)→ 平台置 COMPLETED
```

接口返回不代表做完,做完的信号是回调。

## 3. driver.py 一单的流程(对照 run.log 读)

每单日志在 `integration/platform1/_runs/v<versionId前8位>/run.log`。按顺序出现的行:

| 日志行 | 做了什么 |
|---|---|
| `[回调地址] …` | 解析回调地址:request 里的 `callback_url` → 环境变量 `PLATFORM1_CALLBACK_URL` → `obs_headers_config.json` 当前环境那一节的 `callback_url` |
| `[表] …:N 个待迁移节点` | 解析平台表(`parse_platform_excel`):只取三样——`L*_Name_CN` 拼成节点路径、`Product_Name`(zip 名)、`Product_Obs`(下载地址)。有标记列(是否修改)时,未标记行不下载 |
| (校验) | `optimizeType` 只接受 NONE/MULTI/ALL/不带;`prevObjectkey` 为空(首次优化)退出码 4,不回调 |
| `[停] 表里同一个 Product_Obs 指向多个不同的 zip 名` | 同一个对象挂多个节点名 = 导表错位,下载前停 |
| `[下载] …` | 逐条下载节点 zip 到 `bundle/`(已在且是合法 zip 就跳过;坏件删了重下),再下上一版 skill。下完当场验是不是 zip |
| `[skill] 上一版已解包` / `[skill] 续跑` | 解包 skill,产物目录认 `assets/`;同一工作目录再跑就沿用上次结果 |
| `[迁移] python …migrate_fault_check.py …` | 调技能的迁移脚本(见第 4 节),抓它的全部输出 |
| `[修表] …` | 迁移报"存量调优表有旧版结构病"时,自动加 `--rebuild-tuning` 重跑 |
| `[模型] 起 Claude Code 无头会话…` | 有失败项且开了模型档时,起模型会话处置,完了复跑迁移(见第 4 节) |
| `对应表批量迁移汇总:落地 x/y 行…` | 迁移脚本的结果。符号:`✓` 落地、`=` 未变化跳过、`~` 判据同步、`+` 新增节点、`✂` 删除节点、`✗` 失败 |
| `[部分交付] …` | 有失败行但也有已生效内容:照样打包,清单写进包内 `tree/migration_report.json` |
| `[停] 迁移退出码 …,且包里没有任何已生效的迁移内容` | 一行都没落地,不打包新版 |
| `[失败回传] …` | 上面几种失败,按平台格式回传**未变化的上一版 skill** + 包内 `tree/migration_report.json`(`status=failed`、`reason`),让版本记录闭环 |
| `[产物] …/out/skill_<versionId前8位>.zip` | 新版 skill 打好了 |
| `[回调] 鉴权:复用下载脚本的 invokeToken` | 回调主机和下载端点同主机时,自动用下载脚本那套鉴权 |
| `[回调] <url> → HTTP 200 {"responseCode":"0"…}` | 回调成功。`responseCode` 非 "0" 算失败,带 message 停下 |

## 4. 与技能的两处接线(最重要)

### 4.1 机械层:直接跑迁移脚本

技能的机械部分是一个普通 Python 脚本 `migrate_fault_check.py`,driver 用 `subprocess.run` 起它:

```
python <迁移脚本> --package <bundle目录> --product <产物目录> --auto --map <平台表> [--map-mode all|multi]
```

- `--package`:下载下来的节点 zip 所在目录;`--product`:解包后的 skill 产物目录(`assets/`);
  `--map`:平台表原样喂进去;`optimizeType=ALL/MULTI` 翻成 `--map-mode all/multi`,NONE 走 `--refresh-only`。
- 树结构增删、判据同步、跳过未变化的包、格式检查——**都在这个脚本里**,driver 只负责把文件摆到位、传参、读输出。
- 迁移脚本在哪找(函数 `_find_migrate`):环境变量 `SCOT_MIGRATE_SCRIPT` 显式指定 → 各技能根目录下找,
  独立技能 `cs-scot-migrate/scripts/migrate_fault_check.py` 和发行包内嵌的
  `cs-scot-generate-optimize/migrate/scripts/migrate_fault_check.py` 都可以。技能根目录按序:
  `SCOT_SKILLS_ROOT`(平台装技能的目录)→ 本仓库 `skills/` → `~/.claude/skills`。
- 结果怎么读(函数 `_parse_migrate_result`):用正则从迁移输出里认"落地 x/y 行"和上面那几种符号行,
  拼成一个字典(落地/跳过/失败/新增/删除…),部分交付时写进包里。

### 4.2 模型层:起 Claude Code 无头会话

有失败项(格式检查不过,要改脚本副本)时机械做不了,driver 起另一个子进程:

```
claude --dangerously-skip-permissions -p "<任务文字>" --output-format stream-json --verbose
```

- `claude` 是 Claude Code 的命令行程序;`-p` 是无头模式:不开界面,任务文字当参数,干完自己退出。
- `--dangerously-skip-permissions`:它改文件前不再问"允许吗"(无人值守没人点)。
- `--output-format stream-json`:让它把每一步动作以 JSON 事件流一行一行打出来,driver 边读边翻成人话
  (你在日志里看到的 `[10:24:33] Bash …`、`Edit …` 就是这个),原始事件流落 `model_session.log`。
- 任务文字开头是"用 <技能名> 技能处理一次批量迁移的失败项,只改文件,不用跑命令……"。
  **技能就是在这句话里被点名的**:Claude Code 启动时加载装在 `~/.claude/skills/` 下的技能目录,
  模型看到名字就去读那个技能的 SKILL.md 照着做。技能名怎么定(函数 `_skill_name_for_model`):
  装了独立 `cs-scot-migrate` 就点它;只装了发行包就点前门 `cs-scot-generate-optimize`(前门按输入
  形态自己路由到优化线);`SCOT_MODEL_SKILL` 可显式指定。
- 代码要点(函数 `_model_session`):`subprocess.Popen` 起进程并接管输出管道(`stdout=PIPE`),
  `stdin=DEVNULL` 防止它等键盘输入,`for line in proc.stdout` 一行一行读,超时(默认 3600 秒,
  `PLATFORM1_MODEL_TIMEOUT`)就杀掉、已改的文件保留。Windows 上 `claude` 实际是 `claude.cmd`,
  用 `shutil.which` 解析真实路径;找不到就跳过模型档。
- 会话结束后 **driver 用同一条迁移命令再跑一遍做验证**:格式检查通过了绑定才写入,模型说"改好了"不作数。
  一单只做一轮,没修完的下次点优化在新版基础上继续。
- 换别的 agent 命令行:环境变量 `PLATFORM1_CLAUDE_CMD` 替换整条启动命令,只要它能无头跑、接一句任务。

## 5. 配置与环境变量

配置文件 `obs_headers_config.json`(平台下载脚本的格式,放在 `integration/platform1/`,不进仓库),
我们只多加一个键 `callback_url`:

```json
"beta-dev": {
  "endpoint": "https://<网关主机>/agent/downloadFaultTreeArtifact.do",
  "authType": "invokeToken",
  "invokeToken": "<token 文件路径>",
  "tokenEncrypted": true,
  "callback_url": "https://<网关主机>/agent/workspace/faultTreeNode/optimizeCallback"
},
"default": {"env": "beta-dev", ...}
```

环境变量(都可不设):

| 变量 | 作用 | 缺省 |
|---|---|---|
| `PLATFORM1_ENV` | 用配置文件里哪一节 | 配置文件 `default.env` |
| `PLATFORM1_DL_CONFIG` | 配置文件路径 | 同目录 `obs_headers_config.json` |
| `PLATFORM1_CALLBACK_URL` | 回调地址(优先于配置文件) | 不设 |
| `PLATFORM1_CB_AUTH` | 回调鉴权:`auto` 同主机自动复用下载脚本的 invokeToken / `platform` 强制复用 / `none` 不带 | `auto` |
| `PLATFORM1_CB_HEADERS` | 回调请求头,JSON,设了就以它为准 | 不设 |
| `PLATFORM1_CB_INSECURE` | `1` = 回调不校验对端证书(复用下载鉴权时自动如此) | 不设 |
| `PLATFORM1_CB_ON_FAIL` | `0` = 整单失败时不回传(老行为) | 回传 |
| `PLATFORM1_WITH_MODEL` | 服务模式 `0` = 关模型档 | 开 |
| `PLATFORM1_FAKE_STORE` | 服务模式本地自测:从这个目录拷文件当下载 | 不设 |
| `PLATFORM1_WORK` | 服务模式每单工作目录根 | `_runs/` |
| `PLATFORM1_CLAUDE_CMD` | 模型档的启动命令 | `claude --dangerously-skip-permissions -p` |
| `PLATFORM1_MODEL_TIMEOUT` | 模型会话超时秒数 | 3600 |
| `SCOT_SKILLS_ROOT` | 技能安装目录(可多个,系统路径分隔符分隔) | 不设 |
| `SCOT_MIGRATE_SCRIPT` | 迁移脚本完整路径(显式指定) | 自动找 |
| `SCOT_MODEL_SKILL` | 模型档点名的技能名 | 自动判 |

## 6. 对外接口与回调

**我方接口** `POST http://<本机IP>:8080/optimize`,`multipart/form-data`:

| 字段 | 说明 |
|---|---|
| `versionId` | 平台预生成的版本 UUID,状态须为"优化中";回调原样带回 |
| `excelFile` | 全量表文件流(格式见 `接口说明_给平台.md`) |
| `prevObjectkey` | 上一版 skill 的 objectKey;为空(首次优化)会被拒,退出码 4,不回调 |
| `optimizeType` | `ALL`(全量表、结构以表为准)/ `MULTI`(部分表不动结构)/ `NONE`(只刷引擎);不带 = 老行为(能加不删) |

响应:立刻 `{"result":"success"}`。

**回调** `POST <callback_url>`,`multipart`:`versionId` + `skillFile`(zip 文件流)。请求头按第 5 节的鉴权规则带。
响应 JSON 的 `responseCode` 为 `"0"` 算成功,其他算失败(例如 `40040003` = 版本状态不是"优化中")。
成功回调过的版本不能重发。

**失败也回调**(整单失败时):回传未变化的上一版 skill + 包内 `tree/migration_report.json`。
唯一不回调的是首次优化(没有上一版可回传)。

## 7. 怎么跑

本地模拟一单(不碰网络,货架目录里放好节点 zip 和 skill zip):
```
python integration/platform1/driver.py --request request.json --workdir <工作目录> --fake-store <货架目录> [--with-model]
```

起服务(联调机器):
```
pip install fastapi uvicorn python-multipart
python -m uvicorn server:app --host 0.0.0.0 --port 8080 --app-dir integration/platform1
```
起服务前本地自测:多设 `PLATFORM1_FAKE_STORE=<货架目录>`、`PLATFORM1_WITH_MODEL=0`,用 curl 照第 6 节字段
POST 一发到 `http://127.0.0.1:8080/optimize`,看 `_runs/v<versionId前8位>/run.log` 末尾的 `[产物]`/`[回调]`。

跑测试:
```
python integration/platform1/tests/test_platform1_e2e.py
```

## 8. 常见停点

| 现象 | 原因 | 处理 |
|---|---|---|
| `[停] 表里同一个 Product_Obs 指向多个不同的 zip 名` | 平台导表错位 | 找平台重传各节点的包、重新导表 |
| `下载到的不是 zip … 响应体开头 b''` | 对象不存在/被清理,服务端回 200 空流 | 把 docId 甩给平台 |
| `[停] 迁移退出码 … 没有任何已生效的迁移内容` | 一行都没落地(多为格式检查不过且模型档没修好) | 看迁移输出的 `✗` 行;失败已回传上一版 |
| `responseCode=40040003` | versionId 不是"优化中" | 要新的 versionId |
| `HTTP 404` | 回调 URL 路径/主机不对 | 网关走 443、路径带 `/agent/` 前缀 |
| `连不上 …` | 域名解析不了或端口不通 | `nslookup`;`:8081` 是应用直连口,从外面打网关不带端口 |
| `obs_headers_config.json 不是合法 JSON` | 粘 token 带了换行 | 把值并回一行 |
| `[模型] 找不到命令「claude」` | 起服务的窗口 PATH 里没有 claude | 换窗口或设 `PLATFORM1_CLAUDE_CMD` |
